## Limits of this evidence

- Tests use deterministic promise ordering and local browser/transport doubles. Real iOS/Android LINE handoff, permissions UI, actual push receipt and multi-device behavior were not exercised.
- SQL/RPC deployed state, live pagination datasets, permissions and backend job concurrency were not changed or verified by this PWA workstream. Current source contracts and coordinator-provided baseline were the reference.
- This is not an exhaustive timing proof for every member page. Subscription/transfer/invitation/activation account changes now have deterministic regressions, but native cross-tab event delivery still needs runtime exercise. A browser permission dialog completing after logout and rapid visibility changes while a presence start request is pending remain scenarios for explicit runtime reproduction. UI/API ownership checks prevent stale follow-up work and response installation; they do not cancel browser/server mutations that were already issued for the original account.
- Some SDK calls can wait on SDK-internal session locks independently of a network fetch deadline. Browser/API timeout tests do not prove every internal SDK lock resolves. No speculative SDK timeout or retry redesign was added.
- Mobile runtime internals, main-entry style imports, all CSS, admin code, historical migrations and algorithm computation were outside this writer's edit ownership.
