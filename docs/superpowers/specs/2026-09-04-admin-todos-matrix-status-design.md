# 管理者代辦與 Matrix 狀態設計規格

日期：2026-09-04  
核准：使用者已明確回覆「核准設計，確認，執行」

## 目標與範圍

本次工作分成兩個 PR：

1. PR 1 新增管理者代辦事項，修正 Matrix 狀態判定、來源權限投影、狀態頁觸發卡與手機版展開互動。
2. PR 2 在既有通知工作分支上整合 PR 1 後的 `main`，只發送最高 Matrix 狀態，並以彩種與開獎期別確保整期只通知一次。

所有修改只觸及本需求直接相關的資料表、後端服務、狀態產物、會員投影、管理後臺、Matrix 狀態頁、測試與通知事件。不得重構其他演算法、爬蟲、會員流程、通知類型或全站視覺。

## 不變條件

- 四彩種：今彩539、天天樂、六合彩、大樂透。
- Matrix 分析來源為最新一期開獎資料，分析期數十三期，號碼由小到大，完整驗證。
- 版路類型限加減、合值、拖牌；命中條件為準4+（鎖定1碼）與準5+（鎖定2碼）。
- 天天樂維持 GitHub Actions crawler-only → Supabase → Railway analysis-only，不把爬蟲移回 Railway。
- PWA、Railway、Supabase、管理後臺 AppDeploy 的既有責任邊界不變。
- 「成立次數」與「連準次數」是同一欄位；介面與 API 對外一律使用「連準次數」，不建立第二份數值。

## PR 1：管理者代辦事項

### 資料模型

新增 `public.admin_todos`：

- `id uuid primary key default gen_random_uuid()`
- `admin_id uuid not null references public.admin_accounts(id)`
- `content varchar(100) not null`
- `created_at timestamptz not null default now()`
- `check (char_length(btrim(content)) between 1 and 100)`
- 依 `created_at desc, id desc` 建立清單索引。

資料表位於 exposed `public` schema，因此必須啟用 RLS；撤銷 `anon`、`authenticated` 與 `PUBLIC` 的直接權限，只允許管理後臺伺服器使用既有 service-role 連線。瀏覽器不得持有 service-role key。留言所有權與超級管理員刪除權由管理後臺 API 再驗證，不能信任前端傳入的管理員 ID 或角色。

### 權限與 API

- 所有有效管理員 session 都可列出全部留言。
- 所有有效管理員都可建立留言，`admin_id` 強制取目前 session actor。
- 只有留言本人可編輯內容。
- 留言本人或角色為「超級管理員」者可刪除。
- 空白內容及超過 100 字由 UI、API、DB 三層拒絕。
- 建立時間以 UTC 儲存，使用既有台北時區 helper 顯示；編輯不改寫建立時間。
- 建立、編輯、刪除均防止重複送出；失敗保留輸入與可重試狀態。
- 刪除使用既有 app-owned confirmation，不使用 `window.confirm()`。

### 管理後臺 UI

主選單新增「代辦事項」，沿用既有行動版抽屜與 active module 路由方式。頁面採單一緊湊輸入卡與時間倒序留言清單：

- textarea 有可見標籤、`maxLength=100`、字數計數、錯誤關聯、`resize: none`。
- 建立按鈕只在有效內容時可用，busy 時尺寸不改變。
- 留言卡顯示內容、作者、建立日期時間與依權限出現的編輯／刪除動作。
- 編輯在卡片內完成，保留取消與儲存；失敗不丟失內容。
- 空清單、初始載入、載入失敗、mutation 失敗均有穩定且可恢復的狀態。
- 沿用後臺深藍／金色語彙與既有字級、圓角、邊框；不新增全域 token，不改其他管理模組。
- 360、375、390px 不產生水平溢位；按鈕與卡片不使用不必要的固定寬高，操作目標維持可觸控但視覺緊湊。

## PR 1：Matrix 狀態判定

### 觸發資料模型

每一條成立的狀態判定規則產生一筆 `MatrixStatusTrigger`，至少包含：

- `triggerId`：同一分析產物內穩定且可重現的規則／結果識別。
- `ruleId`：啟動1～2、聚合1～6、共振1～10、臨界1～4。
- `status`：ACTIVE、FOCUS、RESONANCE、CRITICAL。
- `resultKind`：一碼或兩碼。
- `result`：一個單碼或一組不可拆分的兩碼結果。
- `sameCodeRoadCount`：本觸發內唯一實際版路組數。
- `roads`：只包含參與本條規則且符合類型、連準區間與組合條件的版路。

A/B/C/D 與第一／第二類特殊只作內部規則分類，不回傳為畫面標籤。

### 計數與去重

- 加減、合值、拖牌可合併統計，計算實際版路組數，不計版路類型數。
- 每張卡只計入該觸發規則使用的版路，不能把同結果下未參與該規則的其他版路灌入卡片。
- 版路唯一鍵必須由能識別同一實際版路的穩定欄位組成；同一卡片內同一唯一鍵只顯示、只計算一次。
- 同一版路若符合不同觸發規則，可在不同觸發卡中分別計入。
- 【加減＋拖牌】或【合值＋拖牌】只有兩側至少各一組時成立；3/0、0/2、0/4 均不成立。
- 兩碼結果是一組完整結果，絕不把兩個單碼結果拼成兩碼。
- 第一類特殊與第二類特殊互相獨立，各自形成觸發。

### 規則與狀態選擇

啟動1～2、聚合1～6、共振1～10、臨界1～4 的版路類型、結果型態、連準區間、合計門檻、AND 條件及兩側至少一組條件，逐字依使用者核准的原始規格實作，不放寬、不合併、不推導新門檻。

- 首頁：同一期、同一結果只顯示最高狀態；優先序為臨界 > 共振 > 聚合 > 啟動。
- Matrix 狀態頁：保留所有已成立的觸發卡；同一結果可出現在不同狀態卡。
- 狀態卡排序：臨界 > 共振 > 聚合 > 啟動；同狀態依同碼版路數量由大到小，再用穩定識別排序。
- 卡內版路排序：加減 > 合值 > 拖牌；準11進12 > 準9進10 > 準7進8 > 準6進7 > 準5進6；下1期 > 下2期 > … > 下13期；順球1 > … > 順球5。

## PR 1：來源權限與資料防洩漏

分析仍使用完整十三期來源；每筆產出必須保留其既有二期、七期或十三期來源標記，產物壓縮流程不得一律覆寫成十三期。

伺服器依會員權限逐筆投影：

- 二期來源：免費會員完整取得預測號碼、預測期、版路類型、位置、連準次數、同碼版路數量、版路詳情、版路驗證過程。
- 七期來源：所有免費會員可取得預測號碼；週二、週五或推薦資格開放期間可取得完整資料。
- 十三期來源：免費會員只取得預測號碼；Matrix Pro 可取得完整資料。

未授權欄位必須在 API response 形成前移除，以結構化 locked projection 取代；不能先回傳再由 CSS 遮罩。前端對每個受限欄位直接顯示完全一致的「🔒 Matrix Pro」，不能隱藏整張觸發卡、七期／十三期列或預測號碼。驗證過程只在展開且有權限時延遲讀取。

## PR 1：Matrix 狀態頁 UI

### 類別卡片

四彩種、四狀態共用同一 header 結構。左側同一基準線顯示 `•臨界`，其後固定 8px 顯示 `極為罕見版路狀態`；右側數量與狀態名稱水平對齊。整個 header 使用語意化 button 控制展開並提供 `aria-expanded`。

### 觸發卡與版路列表

- 展開類別後，每一個觸發建立一張卡，顯示單碼／兩碼結果、狀態名稱、同碼版路數量、版路詳情與版路驗證入口。
- 表頭、列高、欄位節奏、分隔線與空／錯誤狀態沿用「探索結果區」的 canonical 實作或抽取同一共享樣式，不另做看似相同的平行元件。
- 版路列本身是可鍵盤與觸控操作的 disclosure；點擊後展開驗證過程，有明確 focus-visible、hover、pressed、busy 與 disabled 狀態。
- 「連準次數」只顯示一次，不再顯示「成立次數」。
- 窄螢幕採既有探索結果的欄位壓縮／捲動策略，不在共享頁殼新增 `100vw`、固定高度或 `overflow: hidden`。
- 開合動態只傳達層級，並遵守 `prefers-reduced-motion`。

## PR 2：Matrix 狀態通知

既有 `work/notification-dispatch-20260904-v2` 在 PR 1 合併後以非破壞性方式整合最新 `main`，不重建天天樂 crawler/analysis 邊界。

- 通知 producer 只讀取該彩種該期的最高狀態摘要；沉寂不建立事件。
- 同時成立多個狀態只建立一個最高狀態事件。
- idempotency key 固定為 `matrix_status:<lotteryCode>:<period>`，狀態保留在 payload，不放入 key。
- 同彩種、同開獎期別首次成功建立／派送後，重新分析或狀態升級都不補發。
- producer、ingest 與資料庫唯一限制使用同一事件鍵契約；重試只能完成同一事件，不能建立第二筆。

## 相關衝突清理

- 狀態產物把來源期數固定寫成 13 的覆寫。
