# 管理後台服務控制台與 LINE 暱稱同步設計

日期：2026-08-25  
狀態：待使用者最終審閱

## 目標

1. 用戶管理與訂閱管理顯示 LINE 暱稱，不再顯示 LINE User ID。
2. LINE 登入完成時，自動將 LINE 暱稱同步至會員資料。
3. 系統設定升級為完整且唯讀的安全營運控制台，清楚顯示服務位置、連線狀態、同步統計及真正可執行的維護操作。
4. 不允許在後台修改 API 網址或檢視任何機密金鑰。

## 現況

- 正式管理後台：AppDeploy `matrix-sanqwn`。
- Matrix／會員／通知／LINE API：AppDeploy `app-snsxet`。
- 會員及登入資料：Supabase。
- 系統設定已有基本 AppDeploy、Supabase、健康檢查、Matrix API 與資料更新狀態，但網址、會員同步覆蓋率及個別操作不完整。
- `members` 目前保存 `line_user_id`，LINE 身分資料的 `identity_data.name` 已有暱稱。

## 方案

採用完整安全營運控制台，不採用只顯示少量狀態的簡化方案。

### LINE 暱稱資料模型

在 `public.members` 新增可為空的 `line_display_name text`。

既有的 `private.sync_line_member_from_identity()` 觸發器函式擴充為：

- 僅處理 `provider = 'custom:line'`。
- 從 `auth.identities.identity_data->>'name'` 取得暱稱，去除前後空白。
- 建立會員時同時寫入 LINE User ID 與暱稱。
- LINE 身分更新時同步更新暱稱。
- 暱稱不存在時保留空值，不以 LINE User ID 代替。
- 同步失敗不得阻斷使用者登入，並留下資料庫警告供維運追查。

Migration 會回填既有 LINE 會員的暱稱。LINE User ID 仍保留作內部唯一識別與 API 授權用途，但不顯示於後台表格。

### 管理後台會員資料

`users` 與 `subscriptions` API 回應增加 `lineDisplayName`，表格欄位改為：

- 欄位鍵：`lineDisplayName`
- 顯示名稱：`LINE 暱稱`
- 空值顯示：`未提供`

搜尋、停權確認及訂閱操作中需要辨識會員時，優先顯示暱稱；內部操作仍傳遞會員 UUID，不以暱稱作識別鍵。

### 系統設定資訊架構

頁面分成四區：

1. **整體狀態**
   - 正常、部分異常或異常。
   - 最後完整檢查時間。
   - 正常服務數／總服務數。
   - 全部重新檢查按鈕。

2. **服務位置與連線**
   - 正式管理後台。
   - Matrix API 基底網址。
   - 會員建立／個人資料 API。
   - 通知設定 API。
   - LINE API。
   - Supabase Auth 與 Database 公開服務位置。
   - 每一項顯示網址、狀態、HTTP 狀態、回應時間、最後檢查時間。
   - 網址唯讀並提供複製按鈕。
   - 支援的項目提供個別「重新檢查」或「重新呼叫」。

3. **資料同步**
   - Auth 使用者總數。
   - 會員總數。
   - LINE 登入身分數。
   - LINE 暱稱已同步數與缺少數。
   - 通知設定筆數與最後更新時間。
   - 提供「同步 LINE 暱稱」操作，只允許超級管理員使用。
   - 同步完成顯示檢查數、更新數、略過數與錯誤數，再自動更新畫面統計。

4. **資料更新與排程**
   - 各彩種最後狀態、完成時間與錯誤。
   - 提供「更新狀態」重新讀取最新紀錄。
   - 不新增會實際執行彩券演算法或產生額外運算費用的按鈕。

### 服務檢查語意

- AppDeploy、Supabase Database、Supabase Auth 與公開健康端點使用實際網路或查詢檢查。
- 需要會員權杖的 API 不以匿名成功作為健康條件；匿名呼叫回傳預期的 `401`／`403` 代表路由存在且授權保護正常。
- API 回傳 `5xx`、逾時或無法解析回應才標示異常。
- 「重新連線」不作為通用操作，因為 HTTP 與 Supabase 為無狀態服務；按鈕使用能表達實際行為的「重新檢查」、「重新呼叫」、「同步 LINE 暱稱」或「更新狀態」。

## 安全與權限

- 不回傳或顯示 Supabase service role、anon key、LINE Channel Secret 或任何權杖內容。
- 機密僅顯示「已設定／未設定」；若無法由該服務安全驗證，則不顯示推測結果。
- 系統設定讀取沿用管理員驗證。
- 超級管理員可執行 LINE 暱稱同步；其他角色只能查看並重新檢查安全的唯讀狀態。
- LINE 暱稱屬會員資料，只在已驗證的管理後台顯示。
- 所有同步操作必須可重複執行且結果一致，不建立重複會員。
- 同步操作寫入審計紀錄，但不得記錄 LINE User ID、金鑰或權杖。

## 後端介面

管理後台後端新增或擴充：

- `GET /api/system/status`
  - 回傳分組服務狀態、唯讀服務位置、安全設定狀態與同步統計。
- `POST /api/system/status/:id/retry`
  - 只允許白名單中的安全檢查。
- `POST /api/system/line-profile-sync`
  - 驗證超級管理員。
  - 從 Supabase Auth Admin API 分頁讀取 LINE 身分。
  - 依 `auth_user_id` 更新 `members.line_display_name`。
  - 回傳彙總數字，不回傳 LINE User ID 或完整身分資料。
  - 寫入不含敏感內容的審計紀錄。

Matrix API 若需要提供安全能力狀態，只可新增不含機密值的能力檢查結果；不得公開秘密名稱以外的內容。

## UI 與互動

- 沿用現有後台視覺語言與狀態卡，不重做整個後台。
- 狀態同時使用文字、圖示與顏色，不能只靠顏色。
- 按鈕有 loading、disabled、成功與錯誤回饋，避免重複提交。
- LINE 暱稱同步屬資料寫入，使用既有的應用內確認對話框，不使用瀏覽器 `confirm()`。
- 複製成功提供非阻塞回饋。
- 手機版卡片單欄、桌面版自適應多欄；網址過長可換行且不撐破版面。
- 載入、空資料、部分錯誤與全部異常狀態保持穩定版面。

## 錯誤處理

- 單一服務失敗不得讓整頁失效；顯示該項錯誤並保留其他結果。
- LINE 暱稱同步採逐筆容錯並回傳彙總；個別失敗不回傳敏感錯誤細節到前端。
- 若 Auth 有 LINE 身分但沒有會員資料，同步流程可安全補建會員；不得覆寫已屬於其他會員的 LINE User ID。
- 暱稱缺少時顯示「未提供」，不退回顯示 LINE User ID。

## 測試策略

依測試驅動流程先建立失敗測試，再實作：

1. Migration／SQL 驗證
   - LINE 身分建立與更新會同步暱稱。
   - 既有 LINE 身分可回填。
   - 缺少暱稱不影響登入。
   - anon／authenticated 無權直接執行私有同步函式。

2. 管理後台後端
   - users／subscriptions 映射 `lineDisplayName`。
   - 狀態端點不洩漏機密。
   - 受保護 API 的預期未授權回應被判定為路由正常。
   - LINE 暱稱同步具權限限制、冪等性與安全彙總。

3. 前端
   - 兩個表格顯示「LINE 暱稱」且不顯示 LINE User ID。
   - 缺值顯示「未提供」。
   - 系統設定分組、網址、複製、個別重試、同步確認與結果回饋正確。
   - 鍵盤操作、焦點、loading 與 disabled 狀態正確。

4. 完成驗證
   - 全部自動測試與建置通過。
   - Supabase migration、觸發器、資料回填與 advisors 檢查。
   - AppDeploy 正式後台與 API 部署狀態為 ready，無前後端錯誤。
   - 實際資料確認 LINE 身分數等於已建立會員數，且有暱稱的 LINE 身分皆已同步。
   - 手機與桌面畫面檢查。

## 不在本次範圍

- 後台直接修改 API 網址。
- 顯示或輪替機密金鑰。
- 變更 LINE Channel 設定。
- 新增或恢復演算法自動排程。
- 以 LINE 暱稱作唯一識別或授權依據。
- 重做管理後台整體視覺設計。
