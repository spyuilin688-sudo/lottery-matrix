# Matrix 演算法 API／PWA／營運後台／資料庫完整串接設計

日期：2026-08-21

分支：`api`

狀態：完整設計已確認，待實作計畫

## 1. 目標

完成下列既有功能的正式串接，不改寫既有 UI 流程或已確認的演算法規則：

- Matrix 探索
- Matrix 天衍
- Matrix 天工
- Matrix 狀態
- 樂彩 Matrix PWA
- AppDeploy API 與 AppDeploy Database
- Supabase 會員、訂閱與管理員權限
- 樂彩 Matrix 營運後台

## 2. 資料責任

### 2.1 AppDeploy

AppDeploy 負責：

- 四個彩種官方開獎資料同步。
- Matrix 探索、天衍、天工與 Matrix 狀態演算法執行。
- 完整結果、觸發結果與驗證過程儲存。
- 已完成結果 API。
- 分析版本、工作狀態、結果數量與錯誤資訊。

演算法結果保存 3 天。

### 2.2 Supabase

Supabase 負責：

- 會員與登入資料。
- 訂閱與方案資料。
- 推薦成功人數。
- 使用者自訂狀態觸發條件。
- 管理員與後台權限。
- 既有營運紀錄。

Supabase 不重複儲存版路計算結果、狀態觸發或完整驗證過程。

## 3. 最新開獎後的分析流程

1. 取得官方最新開獎資料。
2. 驗證該彩種資料完整性。
3. 四個彩種分別執行分析，單一彩種失敗不阻塞其他彩種。
4. 產生 Matrix 探索完整結果。
5. 產生 Matrix 天衍完整結果。
6. 產生 Matrix 天工完整結果。
7. 產生第 15 章預設 Matrix 狀態觸發所需的完整分析結果。
8. 完成同一分析版本的摘要、清單、詳情與驗證過程。
9. 完整寫入成功後，才將新版標記為可讀取。
10. 新版尚未完整成功前，不顯示半套新版，也不混用不同分析版本。

結果採「每個彩種先計算完整結果，再由 API 依使用者設定篩選」。API 篩選已完成結果，不重新執行演算法；Matrix 狀態 API 依會員有效設定判定預設或自訂狀態；PWA 不執行演算法。

## 4. Matrix 探索

- 沿用現有加減、合值、拖牌演算法與既有驗證規則。
- `+0` 歸類為拖牌，不計入加減版路。
- 使用者設定只用於 API 篩選已完成結果。
- 結果欄位維持位置、號碼、預測期、連準次數、預測號碼、版路類型與展開驗證過程。

## 5. Matrix 天衍

依《樂彩 Matrix－複合版路 完整規格書》執行：

- 每條複合版路固定保存 2 條成立規則。
- 兩條規則的驗證球位或演算法至少一項不同。
- 同驗證球位且同演算法不得輸出為複合版路。
- 每個歷史驗證組至少一條規則命中即成功。
- 兩條規則各須達 `ceil(N × 30%)` 獨立命中。
- `bothHit` 不計入任一規則的獨立貢獻。
- 最多回推 30 個已完成歷史驗證組。
- 多組最高連準規則合併去重後超過 2 個預測號碼時，該完整搜尋條件不輸出。
- 完整保存兩條規則、獨立貢獻統計、預測資料與歷史驗證資料。
- PDF 附錄 A 的 5 組案例作為正式驗收案例。

PWA 保留已確認的天衍設定與篩選：

- 版路類型固定為複合版路。
- 命中條件固定為準5+（鎖定 2 碼）。
- 連準篩選：準5進6、準6進7、準7進8、準9進10、準11進12、準13進14、準15進16、準17進18+。
- 預設勾選：準9進10、準11進12、準13進14、準15進16、準17進18+。
- 連準篩選只篩選後端已完成結果，不在前端重新計算。

附錄 A 驗收預期：

- 範例 1：不同驗證球位、同演算法；本期預測 03、15。
- 範例 2：不同驗證球位、不同演算法；本期預測 03、34。
- 範例 3：不同驗證期數、不同驗證球位、同演算法；本期預測 03、20。
- 範例 4：不同驗證期數、同驗證球位、不同演算法；本期預測 07、30。
- 範例 5：同驗證球位、不同演算法；本期預測 19、36。

## 6. Matrix 天工

依《Matrix_天工_完整規格書》及本次確認執行。

### 6.1 輸入

- 彩種：今彩539、天天樂、六合彩、大樂透。
- 探索期數：五十期、八十期。
- 探索模式：一段式、二段式。
- 命中條件：準2進3、準3進4。
- 探索球位：固定、依序遞增、依序遞減，可複選。
- 第一段球位與版路類型。
- 二段式時使用第二段球位與版路類型。

### 6.2 搜尋與運算

- 三個來源位置必須等距。
- 所有來源期與等距組合必須完整落在五十期或八十期範圍內。
- 下 N 期不得超過來源至預測結果期之間可驗證的範圍。
- 一段式：探索來源 → 第一段 → 預測結果。
- 二段式：探索來源 → 第一段 → 第二段 → 預測結果。
- 加減範圍：`+1～+49`、`-1～-49`。
- 合值範圍：`1～98`。
- `+0` 歸類為拖牌，不計入加減版路。

### 6.3 結果

- 欄位：間距期數、預測位置、預測、版路類型。
- 完全相同的版路規則與結果去重，只保留一筆。
- 相同預測號碼由不同版路產生時，每條版路分開顯示。
- 結果依間距期數由小到大排列。
- 展開驗證過程沿用 Matrix 探索目前的欄位與排列方式。
- 不顯示近 10 期開獎號碼。
- 不顯示連準篩選。
- 一段式不顯示第二段球位與第二段版路類型。
- 二段式才顯示第二段球位與第二段版路類型。

## 7. Matrix 狀態

依《樂彩 Matrix－第15章 完整規格書》執行。

### 7.1 第 15 章預設分析條件

- 分析期數：十三期。
- 號碼順序：順球。
- 驗證範圍：完整驗證。
- 預設觸發條件使用的版路類型：加減、合值、拖牌。
- 彩種：今彩539、天天樂、六合彩、大樂透。
- 分析位置：各彩種正式位置。

### 7.2 觸發與首頁

- 依 A／B／C／D 與特殊類型完整規則判定。
- 每符合一條規則建立一筆觸發卡片。
- 分別統計啟動、聚合、共振、臨界觸發數量。
- 首頁優先級：`臨界 > 共振 > 聚合 > 啟動`。
- 首頁只顯示最高狀態、該狀態觸發數量與既有狀態文案。
- 首頁的「本期發現 X 組」中的 X 是觸發數量，不是版路數量、同碼版路數量或結果數量。
- 沒有任何觸發時顯示「沉寂 DORMANT」。沉寂不提供自訂觸發條件。

正式觸發門檻：

- 第一類 A（加減、合值單碼一起統計）：
  - 準7進8：1 組為共振，2 組以上為臨界。
  - 準5進6～準6進7：2～4 組為啟動，5～6 組為聚合，7 組以上為共振。
- 第一類 B（加減＋拖牌或合值＋拖牌，兩種來源各至少 1 組）：
  - 準7進8：2 組以上為臨界。
  - 準5進6～準6進7：3～4 組為聚合，5 組以上為共振。
- 第一類 C（拖牌）：
  - 準7進8：1 組為聚合，2 組以上為臨界。
- 第一類特殊：
  - 拖牌準7進8至少 1 組，加減準5進6～準6進7至少 1 組：共振。
  - 拖牌準7進8至少 1 組，合值準5進6～準6進7至少 1 組：共振。
- 第二類 D（加減、合值兩碼結果一起統計）：
  - 準11進12達 2 組以上：臨界。
  - 準7進8～準9進10達 3～5 組：啟動；6～7 組：聚合；8 組以上：共振。
  - 準11進12至少 1 組，加上準7進8～準9進10達 1 組：聚合；達 2 組以上：共振。
  - 準7進8～準11進12達 3 組以上，加上準5進6～準6進7達 6～7 組：聚合。
  - 準7進8～準11進12達 6 組以上，加上準5進6～準6進7達 8 組以上：共振。
- 第二類特殊：
  - 拖牌準7進8～準9進10至少 1 組，加減準5進6～準6進7達 6 組以上：共振。
  - 拖牌準7進8～準9進10至少 1 組，合值準5進6～準6進7達 6 組以上：共振。

加減＋拖牌或合值＋拖牌只有在兩種來源各至少 1 組時成立。

### 7.3 狀態頁

- 保留全部成立觸發，同一結果可出現在不同狀態卡片中。
- 卡片依 `臨界 > 共振 > 聚合 > 啟動` 排列。
- 同狀態內依同碼版路數量排列。
- 同一張卡片內相同版路只顯示一次。
- 不顯示 A／B／C／D 類型名稱。
- 版路詳情依類型、連準次數、預測期、位置的正式順序排列。

### 7.4 自訂狀態觸發條件

固定分析條件仍為四個彩種、十三期與完整範圍。自訂條件只改變狀態觸發判定，不改寫 Matrix 探索、天衍或天工演算法。

設定範圍：

- 今彩539、天天樂、六合彩與大樂透分開設定。
- 每個彩種的啟動、聚合、共振與臨界分開設定。
- 每個狀態分為準4+（鎖定 1 碼）與準5+（鎖定 2 碼）。
- 每個命中條件最多 20 個觸發條件組合。
- 每個組合最多 10 列條件。
- 同一組合內不可有內容完全相同的條件列。
- 不同組合之間允許整組條件完全相同。
- 同一組合的每列條件都滿足時，該組合才成立。
- 同一狀態內，任一組合成立即觸發該狀態。
- 準4+或準5+任一類有組合成立，即觸發該狀態。
- 每個成立的自訂觸發條件組合計為 1 組觸發。

每列條件欄位：

- 連準次數。
- 版路類型。
- 號碼順序。
- 同碼數量，範圍為 1～99。

準4+只能設定鎖定 1 碼，可選連準次數：

- 準4進5。
- 準5進6。
- 準6進7。
- 準7進8。

準5+只能設定鎖定 2 碼，可選連準次數：

- 準5進6。
- 準6進7。
- 準7進8。
- 準9進10。
- 準11進12。

準5+中，兩個版路值即使預測同一個號碼，仍計為 2 碼。

號碼順序每列二擇一：

- 依號碼由小到大排序。
- 依實際開獎順序排序。

版路類型權限：

- 月費以上可選加減、合值與拖牌。
- 季費以上增加複合；年費方案同樣可選複合。

套用與重置：

- 儲存後，自訂條件取代目前選取之彩種與狀態的第 15 章預設觸發條件。
- 儲存只作用於目前選取的彩種與狀態。
- 重置只將目前選取的彩種與狀態恢復為第 15 章預設觸發條件。
- 首頁狀態優先級維持 `臨界 > 共振 > 聚合 > 啟動`。
- 首頁「本期發現 X 組」中的 X 為最高狀態成立的自訂觸發條件組合數量。
- Matrix 狀態頁同步改用自訂判定，並以成立的自訂觸發條件組合顯示觸發卡片。
- 四個狀態都未觸發時顯示「沉寂 DORMANT」。
- 月費資格到期後保留自訂設定但停止套用，改用第 15 章預設條件；續費後恢復套用原自訂設定。
- 季費或年費降為月費後保留全部設定；包含複合版路的組合停止套用，其他組合照常套用。再次取得季費或年費資格後，恢復套用原複合版路組合。

## 8. API 分層讀取

採分層讀取，降低手機首次載入資料量：

- 首頁只讀取四個彩種 Matrix 狀態摘要。
- Matrix 狀態頁讀取觸發卡片與版路清單。
- Matrix 探索、天衍、天工先讀取結果列表。
- 使用者點擊展開時，再讀取該筆驗證過程。
- 每次回傳包含分析版本與開獎期數，禁止混用不同版本。

演算法結果入口：

- `POST /api/matrix/algorithm/explore`
- `POST /api/matrix/algorithm/tianyan`
- `POST /api/matrix/algorithm/tiangong`

狀態摘要、卡片與驗證詳情使用獨立唯讀入口；實際路由名稱在實作計畫中固定。

## 9. 會員與功能權限

AppDeploy API 驗證 Supabase 登入、訂閱、推薦成功人數與管理員權限。前端顯示不是唯一權限防線。

### 9.1 Matrix 探索免費會員

- 七期預設每週二、五開放。
- 推薦成功滿 10 人：七期改為每週一、二、四、五開放。
- 推薦成功滿 15 人：七期永久開放。
- 推薦成功滿 30 人：完整範圍每週二、五開放。
- 推薦成功滿 50 人：完整範圍永久開放。
- 星期統一依台灣時間判定。

### 9.2 Matrix Pro 與方案功能

- Matrix Pro 可使用十三期與完整範圍。
- 季費方案可使用 Matrix 天衍。
- 年費方案可使用 Matrix 天衍與 Matrix 天工。

### 9.3 Matrix 狀態

- 二期來源：免費會員可查看完整內容。
- 七期與十三期來源：免費會員只可查看預測號碼，其餘資訊顯示「🔒 Matrix Pro」。
- Matrix Pro 與試用會員可查看全部內容。
- API 不向無權限帳號回傳被鎖定的完整驗證資料。
- 月費、季費與年費會員可自訂狀態觸發條件。
- 季費與年費會員可在自訂條件中選擇複合版路；月費會員不可選擇複合版路。
- API 在讀取、儲存、重置與套用自訂條件時都驗證會員方案，不只依賴前端顯示限制。

### 9.4 營運後台

- 依 Supabase `admins` 權限驗證。

## 11. PWA 顯示與錯誤狀態

- 保留既有手機 UI、設定流程、結果欄位與展開方式。
- 移除探索、天衍、天工與 Matrix 狀態中的固定假資料，改讀正式 API。
- 自訂狀態觸發條件頁依參考圖保留既有視覺方向，排列依序為 Logo／標題卡、首頁樣式的四彩種切換、四狀態切換、準4+與準5+條件設定、重置設定與儲存設定。
- 自訂狀態觸發條件頁的入口設於 Matrix 狀態頁。
- 準4+與準5+可展開或收合，並顯示目前觸發條件組合數量。
- 每個組合可編輯或刪除。
- 支援局部 Loading，不清空目前成功資料。
- 顯示正式的無資料、分析中、官方資料尚未同步、API 失敗與維護文案。
- 不由前端建立暫時結果、判級、合併、重排或執行演算法。

## 12. 驗收與測試

實作採測試先行。

- 保留並通過現有 Matrix 探索回歸案例。
- 天衍通過 PDF 附錄 A 的 5 組正式案例。
- 天工建立合成驗收案例，覆蓋：
  - 一段式與二段式。
  - 固定、遞增、遞減球位。
  - 等距來源期。
  - 加減、合值、拖牌。
  - 準2進3與準3進4。
  - 下 N 期超出範圍時排除。
  - 完全相同結果去重。
  - 相同預測由不同版路產生時分開顯示。
- Matrix 狀態以第 15 章所有 A／B／C／D 與特殊類型門檻建立單元測試。
- 自訂狀態測試覆蓋：
  - 四彩種與四狀態設定互相獨立。
