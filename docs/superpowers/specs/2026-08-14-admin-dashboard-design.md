# 樂彩 Matrix 管理後臺第一階段設計規格

日期：2026-08-14  
正式專案：`spyuilin688-sudo/lottery-matrix`  
正式分支：`main`

## 1. 目標

在現有 React／PWA 專案新增獨立管理後臺 `/admin`，使用 Supabase Email＋密碼完成管理員登入，並由 Supabase PostgreSQL 保存與提供後臺資料。

本階段建立後臺畫面、管理員登入、資料表結構與資料讀取。不得修改既有會員端頁面、首頁元件、功能流程或視覺規則。

## 2. 本階段範圍

### 包含

- `/admin` 管理員登入頁
- 管理員 Email＋密碼登入
- 未登入禁止查看後臺
- 非管理員禁止查看後臺
- 管理員登出
- 後臺總覽
- 會員管理
- 轉帳審核
- 付款紀錄
- Supabase 資料表
- Supabase Row Level Security 存取規則
- 後臺讀取 Supabase 資料
- 啟動碼管理與批次產生
- 會員兌換方案啟動碼
- 手機與桌面瀏覽器可使用的後臺版面

### 不包含

- LINE 會員資料正式串接
- FastAPI 串接
- 使用者端轉帳申請表單串接
- 確認收款後自動開通會員
- 第三方金流串接
- 年費價格；原規格未確認
- 退款處理；原規格未確認

## 3. 網址與存取

- 後臺入口：`/admin`
- 未登入：顯示管理員登入畫面
- 已登入且具有管理員權限：顯示後臺
- 已登入但沒有管理員權限：不得顯示後臺資料
- 管理員登出後：返回登入畫面
- 重新整理後：由 Supabase Session 判斷登入狀態

管理員身分由 Supabase Auth 使用者與 `admin_profiles` 資料表共同判定，不能只靠前端畫面隱藏。

## 4. 後臺頁面

### 4.1 總覽

顯示：

- 總註冊人數
- 今日註冊人數
- 付費會員人數
- 有效會員人數
- 已到期會員人數
- 今日確認收款
- 本月確認收款
- 累計確認收款

統計值只取自 Supabase 正式資料，不在前端寫死。

### 4.2 會員管理

顯示：

- 會員編號
- LINE 識別資料
- 註冊日期
- 目前方案
- 方案開始日期
- 方案到期日期
- 會員狀態
- 付款紀錄
- 推薦碼／邀請碼

本階段尚未串接 LINE，因此資料表保留 LINE 識別欄位；沒有正式資料時不得自行產生會員資料。

### 4.3 轉帳審核

顯示：

- 會員
- 付款方案
- 轉帳金額
- 轉帳時間
- 帳號末五碼
- 申請時間
- 付款狀態
- 確認收款
- 退回

付款狀態固定為：

- 待確認
- 已確認
- 已退回

本階段建立畫面與資料讀取。確認收款後自動開通會員不在本階段範圍。

### 4.4 付款紀錄

顯示：

- 訂單編號
- 會員
- 方案
- 金額
- 付款時間
- 付款狀態

### 4.5 啟動碼管理

顯示：

- 啟動碼
- 方案期限
- 產生時間
- 啟動碼到期時間
- 使用狀態
- 兌換會員
- 兌換時間

產生規則：

- 僅建立方案啟動碼，不建立付款折抵碼
- 每次固定批次產生 10 組
- 每組只能兌換一次
- 啟動碼為 16 位英文字母與數字
- 顯示格式：`A7K9-P2XM-4Q8R-N6TY`
- 啟動碼自產生日起 1 個月內有效

可選期限：

- 7 天
- 15 天
- 月：30 天
- 季：90 天
- 年：365 天
- 終生

兌換規則：

- 會員方案仍有效：從目前到期日接續延長
- 會員方案已到期：從兌換當日開始計算
- 終生啟動碼：兌換後改為終生

## 5. Supabase 資料結構

### 5.1 admin_profiles

- `user_id`：對應 Supabase Auth 使用者
- `created_at`：建立時間

用途：判斷登入帳號是否具有後臺權限。

### 5.2 members

- `id`：會員編號
- `line_user_id`：LINE 識別資料
- `registered_at`：註冊日期
- `current_plan_id`：目前方案
- `plan_started_at`：方案開始日期
- `plan_expires_at`：方案到期日期
- `status`：會員狀態
- `referral_code`：推薦碼
- `invitation_code`：邀請碼

會員狀態的具體值原規格未確認，本階段不得自行新增固定值。

### 5.3 plans

- `id`：方案編號
- `name`：方案名稱
- `price`：金額
- `duration_days`：方案天數

已確認方案：

- 月費：1,880 元／30 天
- 季費：4,580 元／90 天
- 年費：價格原規格未確認，本階段不建立正式價格

### 5.4 transfer_requests

- `id`：轉帳申請編號
- `member_id`：會員
- `plan_id`：付款方案
- `amount`：轉帳金額
- `transferred_at`：轉帳時間
- `account_last_five`：帳號末五碼
- `submitted_at`：申請時間
- `status`：付款狀態

### 5.5 payments

- `id`：訂單編號
- `member_id`：會員
- `plan_id`：方案
- `amount`：金額
- `paid_at`：付款時間
- `status`：付款狀態

### 5.6 activation_code_batches

- `id`：批次編號
- `duration_type`：7 天、15 天、月、季、年或終生
- `quantity`：固定為 10
- `created_at`：產生時間
- `expires_at`：啟動碼到期時間，為產生時間後 1 個月

### 5.7 activation_codes

- `id`：啟動碼資料編號
- `batch_id`：所屬批次
- `code`：16 位英文字母與數字啟動碼
- `duration_type`：方案期限
- `created_at`：產生時間
- `expires_at`：啟動碼到期時間
- `redeemed_by_member_id`：兌換會員
- `redeemed_at`：兌換時間
- `status`：未使用、已使用或已到期

啟動碼必須由資料庫唯一限制避免重複。兌換時必須在同一筆資料庫交易中完成狀態確認、標記已使用與會員期限更新，避免同一組啟動碼被重複兌換。

## 6. 前端結構

後臺與既有會員端共用同一個 React 專案，但後臺元件與樣式獨立管理。

預計新增：

- 管理員登入元件
- 管理員權限保護元件
- 後臺版面元件
- 總覽頁
- 會員管理頁
- 轉帳審核頁
- 付款紀錄頁
- 啟動碼管理頁
- 會員端啟動碼兌換入口
- Supabase 連線模組
- 後臺專用樣式

既有 `App.tsx` 目前沒有 React Router。本次不得為後臺全面重構既有會員端導覽；只新增可辨識 `/admin` 的最小路由入口，其他網址維持原本 `Prototype` 行為。

## 7. 畫面方向

- 延續樂彩 Matrix 深藍黑、藍色科技光感、白色主要文字、灰色輔助文字
- 後臺資訊以可讀性和資料層級為主
- 手機畫面不得產生欄位碰撞
- 資料欄位較多時使用可閱讀的卡片排列；桌面可使用表格
- 不修改既有首頁 Logo、返回鍵、底部導覽、彩種切換或其他會員端元件

## 8. 資料流

1. 管理員在 `/admin` 輸入 Email 與密碼。
2. React 透過 Supabase Auth 驗證。
3. 登入成功後查詢 `admin_profiles`。
4. 具有管理員資料才可讀取後臺資料。
5. 後臺從 Supabase 讀取會員、方案、轉帳、付款與啟動碼資料。
6. 管理員選擇期限後，每次產生 10 組啟動碼。
7. 會員提交啟動碼後，系統確認啟動碼未使用且未到期。
8. 有效方案會員從原到期日延長；已到期會員從兌換日開始；終生碼將會員改為終生。
9. 啟動碼與會員期限更新必須同時成功，否則全部取消。
10. 登出後清除 Supabase Session 並返回登入畫面。

## 9. 錯誤處理

- 登入失敗：登入頁顯示失敗狀態
- 無管理員權限：不得顯示後臺資料
- Supabase 未設定：後臺不得假裝已連線
- 資料讀取失敗：對應區塊顯示讀取失敗狀態
- 沒有資料：顯示空資料狀態，不建立示範會員或付款資料
- 啟動碼無效、已使用或已到期：不得更新會員期限
- 啟動碼兌換部分失敗：不得只更新其中一張資料表

錯誤狀態的具體文案原規格未確認，實作前不得自行加入正式文案。

## 10. 驗證

必須驗證：

- `/admin` 可正常開啟
- 未登入不能看到後臺
- 非管理員不能看到後臺
- 管理員可登入與登出
- 重新整理後登入狀態正確
- 五個資料表可建立
- Row Level Security 不允許非管理員讀取
- 總覽數值來自資料庫
- 會員、轉帳、付款與啟動碼資料可讀取
- 手機與桌面版面無重疊、超界或碰撞
- 每次產生 10 組格式正確且不重複的啟動碼
- 啟動碼產生後 1 個月到期
- 同一組啟動碼只能成功兌換一次
- 有效會員從原到期日延長
- 已到期會員從兌換日開始
- 終生碼兌換後會員為終生
- 既有會員端頁面除啟動碼兌換入口外維持原狀
