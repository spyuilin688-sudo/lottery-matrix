# 個人頁面與推薦碼設計規格

## 目標

完成「我的推薦碼／啟動碼」、「我的」、「Matrix Pro 會員方案與收費標準」及「更新紀錄」的指定介面調整，並將推薦碼由唯讀畫面改為受登入會員身分保護的實際功能。

## 範圍

- 只修改個人頁面、推薦碼、啟動碼、會員方案、更新紀錄及其直接使用的會員 RPC／資料庫規則。
- 不改變付款、退款、訂閱、啟動碼、探索權限或管理後台的既有流程。
- 推薦成功人數沿用現有規則：受邀會員的付款紀錄存在 `confirmed` 狀態時才計入；不新增付款狀態或退款流程。
- 啟動碼維持目前可在付款後填寫與使用的規則；推薦碼的付款前限制不套用於啟動碼。

## 推薦碼資料與權限

### 會員可讀資料

新增 `member_referral_summary` RPC，僅供已登入、有效且具有 LINE 身分的本人呼叫。回傳：

- 本人的推薦碼。
- 本人的推薦成功人數。
- 本人是否已輸入推薦碼。
- 本人是否仍可輸入推薦碼。

推薦碼由伺服器端在首次讀取時建立，並保證與其他會員推薦碼不重複。前端不直接讀取或更新 `members` 資料表。

### 輸入規則

新增 `member_referral_submit(p_referral_code text)` RPC。輸入值會在伺服器端去除前後空白並統一大小寫後驗證。

提交成功必須同時符合：

1. 呼叫者已登入、為有效會員，且已有 LINE 身分。
2. 呼叫者尚未輸入過推薦碼。
3. 呼叫者尚無任何 `payments.status = 'confirmed'` 的付款紀錄。
4. 推薦碼存在，且不是本人推薦碼。

提交會在單一資料庫交易中鎖定本人與推薦碼擁有者資料後，僅寫入本人的 `invitation_code`。同一 LINE 帳號不能再次提交。推薦成功人數不會在提交當下增加；僅在受邀會員付款紀錄為 `confirmed` 時由既有計算規則反映。

RPC 必須：

- 使用受限的 `security definer` 實作、空白 `search_path`，並在函式內驗證 `auth.uid()`。
- 只授權 `authenticated` 執行；撤銷 `public` 與 `anon`。
- 回傳固定錯誤碼給前端顯示，包括格式錯誤、找不到推薦碼、填寫本人推薦碼、已填寫、已有確認付款與一般提交失敗。
- 為推薦碼增加不分大小寫的唯一性保護，避免並行建立重複值。

## 推薦碼／啟動碼頁面

- 頁面內容左右間距為 16px。
- 「推薦成功認定」、「推薦成功獎勵」、「推薦獎勵補充規則」、「啟動碼使用說明」收合按鈕改為文字上下各 4px，不保留固定最小高度。
- 推薦碼與啟動碼的「確認」按鈕高度由 48px 改為 40px；字級不變。
- 頁面載入時讀取推薦碼摘要；讀取失敗時顯示錯誤且不以假資料取代。
- 推薦碼輸入框在空白、載入中、提交中、已填寫或不可填寫時不可提交。
- 提交成功後清空輸入值、更新可提交狀態並顯示成功訊息；失敗時保留輸入值並顯示對應訊息。

## 「我的」與聯絡頁

- 移除「客服與支援」群組及其中的「聯絡客服」、「問題回報」、「商務合作」選項。
- 在「法律資訊」群組最後新增唯一選項「聯絡客服/問題回報/商務合作」。
- 進入後頁面左右間距為 16px，依序顯示三張卡片：「聯絡客服」、「問題回報」、「商務合作」。
- 每張卡片標題下方皆顯示 `Matrix1150801@gmail.com`，卡片垂直間距為 8px。
- 舊的內部畫面識別值仍導向合併後頁面，避免既有返回或暫存導覽失效；它們不再出現在「我的」頁面。

## 會員方案／收費標準

- 費用方案卡使用 17px 左右間距；輪播仍維持流式寬度與滑動行為，不使用鎖死的裝置寬度。
- 管理訂閱卡與「確定付款」按鈕使用 16px 左右間距。
- 管理訂閱卡內所有可見文字使用粗體。
- 「自動續訂」文字與左側勾選框間距為 4px；勾選框縮為與 12px 文字高度相近的尺寸。
- 清理目前 18px 方案頁間距的重複覆寫，使方案卡與結帳區間距各自只有一個最終來源。

## 更新紀錄

- 保留「更新紀錄」頁面與標題。
- 移除目前頁面內的訊息卡與文字。
