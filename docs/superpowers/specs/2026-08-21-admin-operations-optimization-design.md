# 後臺營運功能優化設計

## 已確認需求

### 用戶管理

- 可搜尋及篩選會員。
- 可查看會員資料、方案、到期日、推薦碼及邀請碼。
- 可啟用或停用會員。
- 停用會員不得使用登入後及會員專屬功能；公開功能維持可用。
- 手機版使用卡片，桌面版使用表格。

### 訂閱管理

- 可手動開通、續訂、取消、調整到期日及設定終生會員。
- 可審核轉帳申請及查看付款紀錄。
- 取消訂閱僅停止自動續訂，會員權限保留至到期日。

### 管理員權限

- 角色固定為超級管理員、營運管理員、查看人員，權限依角色統一套用。
- 功能權限區分用戶管理、訂閱管理、啟動碼管理及系統設定。
- 管理員可修改自己的名稱。
- 不得刪除自己。
- 系統必須保留至少一位啟用中的超級管理員。
- 所有管理操作寫入審計日誌。

### 系統設定

- 進入頁面時自動檢查，並提供「重新檢查」。
- 顯示後臺 AppDeploy、API AppDeploy、Supabase Database、Supabase Auth、健康檢查 API、Matrix coverage API、Matrix audit API、Matrix algorithm cases API，以及四個彩種資料更新排程。
- 每項顯示項目名稱、項目說明、正常或異常、最後檢查時間、回應時間、錯誤內容及排程最後執行狀態。
- 項目說明如下：
  - Supabase Database：儲存會員、訂閱、付款及管理員資料。
  - Supabase Auth：處理會員登入、登出及帳號驗證。
  - 健康檢查 API：確認 Matrix API 服務是否正常運作。
  - Matrix coverage API：檢查四個彩種的資料涵蓋範圍與筆數。
  - Matrix audit API：檢查開獎資料是否缺期、重複或異常。
  - Matrix algorithm cases API：取得演算法案例與計算結果。
  - 後臺 AppDeploy：顯示後臺系統的部署及服務狀態。
  - API AppDeploy：顯示 Matrix API 的部署及服務狀態。
  - 資料更新排程：顯示各彩種自動更新資料的執行狀態。
- 手機版每個連線項目使用獨立卡片。

## 架構

- 後臺 API 維持 AppDeploy backend router，資料寫入沿用 Supabase service role transport。
- `members` 增加 `auto_renew`，訂閱取消只把此欄位改為 `false`。
- 新增 `system_job_status` 保存四個彩種排程的開始、成功、失敗及錯誤。排程開始時先寫入執行中，完成後寫入成功，捕捉錯誤後寫入失敗。
- 後臺連線狀態 API 獨立檢查各服務；單一項目異常不會清除其他項目的結果。
- 角色權限由後端固定角色矩陣判定，前端只顯示結果，不提供每位管理員個別勾選。
- 所有會員、訂閱、轉帳及管理員異動沿用 `audit_logs`。

## 畫面

- 桌面版用戶與訂閱資料使用現有表格結構，增加搜尋、篩選及操作欄。
- 760px 以下改用卡片，操作按鈕不依賴橫向捲動。
- 系統設定使用狀態卡片；狀態名稱與說明在左，狀態與時間在右，手機版改為上下排列。

## 驗證

- 後端單元測試涵蓋會員停用、訂閱取消／開通／續訂／終生、轉帳審核、角色矩陣、自我刪除及最後超級管理員保護。
- 狀態測試涵蓋各端點獨立成功與失敗、回應時間、說明文字及排程資料映射。
- API app 測試涵蓋停用會員拒絕會員專屬 API，以及排程狀態寫入。
- 執行 admin test、admin build、根專案相關 test 及 build。
