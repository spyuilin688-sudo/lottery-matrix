# 樂彩 Matrix 全專案手機響應式 A 方案設計

日期：2026-08-26

## 目標

保留目前 390px 黑金介面的視覺、功能、資料流程與文字，將全專案使用者頁面及管理登入頁收斂為 320px～430px 連續響應式版型。不同手機寬度下，內容必須自行換行、縮排或重排，不得截字、超出畫面或需要左右拖動整個頁面。

## 核准範圍

- 使用者頁面、設定頁、方案頁、登入／重新登入狀態、成功／錯誤提示與所有現有功能頁。
- 管理員登入頁與手機可到達的管理入口；管理資料表若需要保留欄位比較，可使用明確的表格內水平捲動，但整個頁面不得水平溢出。
- 將目前 13 個 `window.confirm()` 與 1 個 `window.alert()` 改成同一套專案內 React Dialog。
- 以使用者提供的成功、警告、錯誤及確認畫面作為色調與資訊層級參考；參考圖不會直接當成網頁圖片貼上。

## 不在本次範圍

- 不增加或刪除任何功能。
- 不改登入、付款、訂閱、刪除、儲存、API、資料庫或權限邏輯。
- 不把手機版擴張成平板／桌面重新設計。
- 不新增 PWA manifest、service worker 或離線資料能力；這是後續獨立工作。
- 不用整頁 `transform: scale()`、固定寬畫布或裁切內容假裝響應式。

## 響應式版型決策

### 手機畫布

- 390px 是視覺基準：在 390px 不主動改變既有字級、色彩、卡片比例與資訊順序。
- 支援寬度為 320、360、375、390、412、430px，並且在兩個測試寬度之間連續適配。
- 共用 App Shell 使用 `width: 100%` 與 `max-width: 430px`，內容寬度由父層決定；不再把所有較寬手機固定在 390px。
- 頁面左右安全外距由單一 token 控制，並加上 `env(safe-area-inset-*)`。
- 所有 grid／flex 子項預設可縮小 (`min-width: 0`)；主要文字可換行，重要名稱與錯誤訊息不可省略。

### 元件重排

- 卡片、欄位、列表與操作列優先使用百分比、`minmax(0, 1fr)`、`max-width` 及必要的 `clamp()`。
- 兩個短按鈕在一般手機維持左右排列；320px 或文字放大造成空間不足時改為上下排列，主要／危險動作放在後面。
- 所有重要觸控操作區以約 44×44 CSS px 為目標；不得為了縮小視覺而縮小實際可點擊區。
- 底部導覽保留既有位置與選取狀態，加入左右及底部安全區，且不得遮住最後一段內容或鍵盤焦點。
- 固定高度只保留圖示、彩球及具有明確幾何意義的元件；文字容器與彈窗不使用會截字的固定高度。

## 共用 Dialog 決策

### 唯一擁有者

- 建立共用 `AppDialogProvider`、`useAppDialog()` 與 `AppDialog`，使用專案已安裝的 Radix Dialog 作為焦點與鍵盤行為基礎。
- `confirm(options): Promise<boolean>` 取代 `window.confirm()`；`alert(options): Promise<void>` 取代 `window.alert()`。
- 原事件處理器改為等待結果後執行原本分支，不能改變儲存、刪除、登出、續訂或付款的實際行為。

### 類型與外觀

- `success`：綠色，僅用於已被既有程式確認完成的結果。
- `warning`：金／橘色，用於一般確認、尚未儲存、重新登入與功能限制。
- `danger`：紅色，用於失敗、刪除及不可逆風險。
- Dialog 保留深藍底、金色邊線與既有 Matrix 視覺；標題、說明與按鈕文字沿用目前繁體中文內容。
- 危險 Dialog 的取消按鈕取得初始焦點；付款只保留既有確認提示，不新增或模擬付款結果。

### 可操作性

- 開啟時焦點進入 Dialog，Tab 不離開 Dialog，Escape 等同取消，關閉後焦點回到原按鈕。
- 背景不可操作，Dialog 不超出 visual viewport，長內容在 Dialog 內捲動，標題與操作保持可到達。
- 使用全域 layer token：Backdrop、Dialog、Toast 各有固定層級；不使用任意 `9999`。
- 遵守 `prefers-reduced-motion`；窄螢幕與 200% 縮放仍可完成操作。

## 設計系統與文件

- `src/design-tokens.css` 繼續是 runtime token 的唯一來源；`DESIGN.md` 是說明鏡像，不建立第二套 token。
- 更新 `DESIGN.md`：390px 改為視覺基準，支援畫布上限為 430px。
- 更新 `UX-CONTRACT.md`：新增 Dialog／Alert Dialog 唯一擁有者、類型、焦點、手機重排與驗證規則；14 個原生對話框風險在全部遷移後移除。
- 既有 2026-08-22 功能頁響應式規格仍有效；本規格補足全專案殼層、未涵蓋頁面與共用 Dialog。

## 測試與驗收

### 測試先行

- 每一批 production 修改前先加入會失敗的需求測試，再做最小修正直到通過。
- 靜態合約測試禁止新增 `window.alert`、`window.confirm`、`window.prompt`、固定手機畫布與頁面級水平裁切。
- Dialog 元件測試涵蓋標題／說明、確認／取消結果、Escape、焦點移入／回復與 danger 初始焦點。

### 六種手機寬度

在 320、360、375、390、412、430px 逐頁檢查：

- `document.documentElement.scrollWidth <= clientWidth`；資料表的明確內部捲動區除外。
- 可見文字、按鈕、輸入框、卡片及 Dialog 均在視窗內，沒有截字或重疊。
- 最後內容不被底部導覽及安全區遮住。
- 重要操作的觸控區可用，鍵盤焦點可見。
- 390px 與目前核准視覺相比沒有非必要變形。

### 完整驗證

- 執行相關單元測試、Node 合約測試、Playwright 手機矩陣、TypeScript／runtime check、production build。
- 分別執行 Frontend Design Premium report 與 strict audit；靜態 audit 不能取代瀏覽器測試。
- 只在所有修改檔案、測試與最新 GitHub main 都核對完成後回報完成。

## GitHub 安全策略

目前工作區副本落後 GitHub main，且含有既有測試輸出異動。本次不覆蓋或刪除這些既有檔案；實作前必須以 GitHub main 最新版本建立乾淨基準，再把本規格的變更套用並驗證。
