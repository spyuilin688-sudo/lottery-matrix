# 管理者後臺審計、API 狀態與啟動碼設計

## 目標

1. 超級管理員的操作不寫入、也不顯示於審計日誌。
2. 系統設定依實際服務位置分組，以適合手機閱讀的精簡列顯示目前使用中的 API／RPC 狀態與位置。
3. 驗證啟動碼的建立、兌換與訂閱更新流程；只修正驗證中確認的缺陷。

## 範圍

### 審計日誌

- 保留現有應用層 `writeAudit` 對超級管理員的跳過規則。
- 保留資料庫 `skip_super_admin_audit_logs` trigger，阻止超級管理員操作新增至 `audit_logs`。
- 審計日誌讀取時連接 `admin_accounts`，排除角色為「超級管理員」的紀錄，使舊資料亦不顯示。
- 不刪除既有審計資料，不改變其他管理員的審計流程。

### 系統設定 API 狀態

- 依 AppDeploy、Supabase、Railway 三個實際位置分組。
- 每個項目使用精簡列，不使用大型獨立卡片。
- 每列固定顯示：API／RPC 名稱、位置、狀態、最後檢查時間、回應時間；異常時顯示既有的安全錯誤摘要。
- 保留四個彩種資料更新排程及既有手動更新按鈕。
- 不在前端或回應資料中暴露 Service Role Key、Worker Token 或其他密鑰。

#### AppDeploy

- 管理者後臺 API：以既有健康檢查端點確認服務狀態。

#### Supabase

- Auth API、Database API、Matrix Status Edge Function。
- Matrix 探索、天衍、天工、自訂狀態、會員、通知、付款與啟動碼等目前由 PWA 直接呼叫的 RPC。
- 讀取型 API 可使用安全的非寫入檢查。
- 寫入型 RPC 不以實際寫入作為健康檢查；改由 Supabase API 結構確認端點存在，並繼承 Supabase Database／Auth 的連線結果。

#### Railway

- `/health`、`/jobs/status`、`/jobs/refresh`。
- `/api/matrix/cards/*`、`/api/matrix/latest/*`、`/api/matrix/history/*`、`/api/matrix/tongxing`、`/api/matrix/number-reference`。
- GET 型端點使用安全讀取檢查；POST 型端點不送出會變更資料的實際請求，改由 Railway 服務健康狀態與既有路由清單確認。
- 四個彩種排程維持獨立狀態列。

## 啟動碼驗證

- 管理後臺可選擇 7、15、30、90、365 天或永久，且每次批次建立 10 組。
- 7、15、30 天啟動碼授予月費方案權限；90 天授予季費方案權限；365 天授予年費方案權限；永久啟動碼授予終身方案權限。
- 會員兌換較低方案啟動碼時只延長天數，不降低目前有效權限；兌換較高方案啟動碼時立即升級並延長天數。
- 使用者輸入會正規化為大寫 `XXXX-XXXX-XXXX-XXXX`。
- 未登入、格式錯誤、不存在、已使用、已過期及永久會員重複兌換均不得更新會員資料。
- 有效的天數型啟動碼從「目前到期日」與「兌換時間」較晚者開始累加。
- 永久啟動碼將會員設為永久並清除到期日。
- 成功兌換後，同一交易內將啟動碼標記為已使用並記錄兌換會員與時間。
- 驗證正式遷移順序後，確認 `authenticated` 可執行 `redeem_activation_code`，只有後臺 Service Role 可執行 `generate_activation_code_batch`。
- 補足資料庫函式、權限、前端錯誤狀態及後臺流程的自動測試；不建立真實啟動碼或修改正式會員資料作為健康檢查。

## 響應式與相容性

- 系統設定沿用現有後臺斷點、字級、按鈕與顏色。
- API 分組與精簡列在窄螢幕改為可換行的資訊列，不設定會造成水平溢出的固定寬度。
- 既有重新檢查、Railway 重新呼叫與四彩種手動更新流程保持不變。

## 錯誤處理

- 單一 API 檢查失敗不阻斷其他項目。
- 無法安全獨立探測的寫入型 API，明確依其服務連線與端點存在性判定，不執行寫入。
- API 回應只保留狀態、時間與已白名單化的摘要，不傳回原始錯誤或設定內容。

## 測試

- 審計日誌查詢排除超級管理員，並保留其他角色。
- 應用層與資料庫層仍阻止超級管理員審計寫入。
- 系統狀態完整列出目前程式直接使用的 API／RPC、位置與分組。
- 各項檢查互相隔離；密鑰與原始錯誤不出現在回應。
- 390px 手機寬度下無水平溢出，操作按鈕仍可點擊。
- 啟動碼六種期限、格式、單次使用、過期、訂閱累加、永久會員與 RPC 權限均有回歸測試。
- 執行管理後臺單元測試、PWA 單元測試、Python 測試、正式建置與直接相關的靜態檢查。

## 不修改項目

- 不新增新的管理者角色或權限。
- 不改變四個彩種排程、爬蟲來源或演算法。
- 不刪除既有審計資料。
- 不修改訂閱方案價格、期限或其他會員流程。
- 不實際呼叫會建立、刪除、兌換或更新資料的 API 作為狀態檢查。
