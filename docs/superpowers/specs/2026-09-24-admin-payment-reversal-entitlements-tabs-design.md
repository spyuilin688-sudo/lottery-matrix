# 訂閱管理：超級管理員沖銷同步會員權益與三分頁設計

日期：2026-09-24。基準：`lottery-matrix/main` 的 `fb755fe26bf7d91fba1dd301cc7870ab41d28912`；僅在獨立分支修改。使用者確認採 A：只撤回該筆付款帶來的權益，其他有效來源保留；既有資料若無法可靠區分，不做部分寫入。

## 目的與既有行為

「訂閱管理」目前依序顯示訂閱會員、付款紀錄與沖銷、轉帳申請三區。付款沖銷目前允許具訂閱編輯權限的營運管理員，資料庫只更新 `payments.status` 與沖銷欄位，不更新 `members.current_plan_id`、`plan_started_at`、`plan_expires_at`。本次變更限於沖銷權限、沖銷後會員方案／效期與此頁三分頁；不觸發綠界退款，也不改動轉帳審核、其他訂閱操作或付款成立規則。

## 沖銷後權益規則

- 對實際已開通的 `confirmed` 付款，將該筆移出會員權益計算，其餘已確認付款依原付款時間與方案天數重新套用既有「從付款時間或當時效期較晚者起累加」規則；保留其他付款的時數與方案。以前一筆較早的成功付款時間作為剩餘權益開始時間，最後一筆有效開通付款決定方案。計算使用資料庫時間戳精度及方案實際 `duration_days`。
- 若沒有任何剩餘有效付費來源，而且已證實目前權益僅來自這些付款，將付費方案、開始與到期欄位清空，會員與獨立免費試用資料不變。若尚有確認付款，即使其效期已過，也保留該筆的歷史到期時間；會員是否有當下的付費資格仍由既有到期判斷決定。
- `refund_required` 付款原本未開通會員；記錄這種付款的沖銷不扣除會員天數或改變方案。原轉帳申請或綠界訂單狀態不自動改寫，保留目前付款與審核紀錄各自獨立的契約。
- 其他權益來源（人工調整、啟動碼、終生權限）不可被付款重算覆蓋。資料庫須先在同一交易的會員鎖下，按所有尚未沖銷的已確認付款重現沖銷前方案、開始、到期、終生與自動續訂狀態，並與會員目前狀態精確比對。只有能重現的付款來源才自動重算；付款時間／方案資料不完整或目前狀態無法由付款完整重現，回傳明確衝突，不修改付款、會員或稽核資料。此檢查涵蓋已存在及之後出現、但目前無法可靠拆分的其他權益；不從付款清單推論或抹去它們。
- 重複送出同一付款的同種沖銷結果，回傳首次保存的結果，不再次修改效期；不同結果衝突。原有原因長度限制、已完成外部退款／刷退／交易取消的前提及推薦成功計數維持。

已知兩筆綠界成功付款的核對例：月費在臺灣時間 2026/09/23 22:08:07，年費在 2026/09/24 02:19:24；原到期 2027/10/23 22:08:07。若沖銷年費，應回月費並到期於 2026/10/23 22:08:07；若沖銷月費，應保留年費，以年費付款時間起算，到期約 2027/09/24 02:19:24。秒以下仍以資料庫原始時間為準。不在正式資料上執行測試沖銷。

## 權限、交易與錯誤

- 前端只讓超級管理員且具既有訂閱編輯權限者看見「記錄沖銷」；非超級管理員可依現有查看權限查閱付款紀錄，其他訂閱／轉帳按鈕權限不變。
- `PUT /api/payments/:id/reversal` 在既有管理員工作階段與訂閱編輯檢查之外增加超級管理員角色驗證，拒絕繞過畫面的要求。資料庫同簽名 RPC 再核對服務端呼叫及執行者是啟用中的超級管理員；不接受客戶端傳送的角色或執行者身分。
- RPC 先取得目標付款對應會員，再鎖定會員、付款，於鎖內驗證現況與重算，並一次提交付款狀態、會員欄位及現有稽核資料。並行的付款確認／訂閱修改與沖銷不得讓計算使用舊的會員狀態。衝突以限定的錯誤代碼返回前端；不確定是否成功時應重新讀取付款與會員狀態，不自動再次送出不同結果。
- 確認視窗改為明確說明「此處只記錄已在外部完成的沖銷，不會匯退款項；成功後會同步重算會員方案與效期」。成功時重新讀取付款列表與訂閱會員列表，失敗時保留輸入及可辨識的錯誤；若資料無法確認來源，顯示需要核對權益的提示且資料保持原狀。

## 手機與桌面分頁

- 在「訂閱管理」頁頂加入三個分頁：「訂閱會員」「付款紀錄」「轉帳申請」，手機一列呈現、以現有深色金色樣式標示選取；桌面共用同一行為，不使用固定內容高度或整頁橫向捲動。
- 每次只顯示目前分頁；訂閱會員保留原搜尋、方案篩選、表格與資料頁碼；付款紀錄保留原搜尋、紀錄、沖銷表單與資料頁碼；轉帳申請保留手機通知設定、既有搜尋與審核、資料頁碼。切換功能分頁不等於更換列表的資料頁碼，各分頁的篩選和頁碼在同一次進入頁面期間保留。
- 分頁使用語意按鈕、選取狀態、鍵盤焦點與方向鍵操作；手機文字不截斷、觸控區沿用既有後台尺寸。付款分頁直接呈現紀錄，避免進入後只看見第二層收合標題；原本的確認流程仍使用既有共用確認視窗。
- 原有轉帳推播連結 `#transfer-requests` 在首次開啟及已開啟頁面收到連結時，皆選中轉帳申請分頁並顯示內容。切離付款分頁不保留隱藏且可送出的沖銷表單。

## 驗收與範圍

僅執行 `AGENTS.md` 允許的明確相關測試檔案：資料庫測試涵蓋年費／月費任一筆沖銷、最後一筆、未開通付款、其他權益導致的全交易衝突、重試及非超管；後端測試涵蓋直接呼叫的角色拒絕；前端測試涵蓋手機分頁、推播定位、非超管隱藏操作及成功後兩種列表同步。對相關 UI 執行窄版與一般版視覺檢查，核對現有 `DESIGN.md` 與 `UX-CONTRACT.md`；更新其受本設計取代的沖銷與區塊描述。正式環境不以真實會員付款驗證沖銷，不執行全專案測試。
