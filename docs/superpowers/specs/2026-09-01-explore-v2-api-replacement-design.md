# Matrix 探索 v2 演算法 API 替換設計

## 目標

以 `Matrix_探索功能_三版路演算法_API_完整修正版_v2_20260901.md` 取代目前探索功能與 Matrix 狀態共用的三版路運算核心；探索頁面與既有 RPC 回傳欄位不變。

## 現況與替換範圍

目前共用探索核心位於 `services/matrix-api/app/domain/explore_shared.py`，由 `explore_shared_v8.py` 和 `artifact_builders.py` 呼叫。現行核心有 `TIANYAN_HISTORY_LIMIT = 30`，且鎖定 1 碼、鎖定 2 碼僅取 8／12 組作最終判定；這不符合 v2 的完整歷史搜尋與完整延續判定。

新核心取代此共用運算路徑，保留以下對外契約：

- `matrix_explore_list` 與 `matrix_explore_validation` 的請求及回傳欄位。
- 探索結果欄位、驗證資料欄位與既有前端顯示。
- Matrix 狀態由探索 artifact 讀取結果的資料流程。

## 核心資料流

1. 依彩種、排序方式、位置、號碼建立完整歷史 `LockKey` occurrence 索引。
2. 一次建立十三期來源資料；二期、七期、十三期僅以 `lockedSourceIndex` 篩選。
3. 同一鎖定條件只取得一次 B、C、D、E… occurrence 串列，供三版路分流。
4. 拖牌僅讀取各 occurrence 的 locked cell；加減與合值只建立一次完整 range cells，排除 locked cell。
5. 標準範圍從完整 range cells 移除 `FULL_ONLY` cells；標準與完整各自執行候選、共同值、連準和有效性判定。
6. 完整通過後才產生結果、驗證資料及 artifact 列。

## 三版路與候選

- 加減：依彩種最大值循環，`+0` 可用。
- 合值：保存完整合值，預測時轉回合法號碼。
- 拖牌：驗證資料限鎖定條件本身，`+0` 可用，不使用 range cells。

候選值在每一池先去重。加減與合值共用相同 range cells，但各自計算候選值。禁止建立 occurrence、cell、候選值、共同值、pair 的笛卡兒積。

## 連準狀態機

### 準4+（鎖定 1 碼）

- B 與 C 無共同值時停止。
- 有共同值時延續至不能延續。
- 準4進5至準7進8有效；確認準8進9或更長時整條無效，不得截短。

### 準5+（鎖定 2 碼）

- 最終必須恰好兩條不同規則；預測同碼時顯示去重後的一碼。
- B、C 無共同值時保留最多十個候選並繼續往後；第二共同值可在任何後續 occurrence 出現。
- 同一驗證組命中兩值只計一次連準。
- 準5進6、準6進7、準7進8、準9進10、準11進12有效；確認準12進13或更長時整條無效，不得截短。
- 單次值只能位於連準區間中間。

三版路皆在完整延續後才判定相同最長連準的候選值數量；大於兩值時整條無效，不得兩兩組合輸出。

## Artifact、RPC 與版本

- 探索 artifact 僅保存已完成有效性判定的結果與其驗證資料。
- Matrix 狀態繼續讀取同一份探索 artifact，不新增前端資料來源。
- 新分析版本和 `matrix_explore_list`、`matrix_explore_validation` 的 analysis version 條件必須同步更新，避免 Worker 產物無法被 RPC 讀取。

## 測試

- 覆蓋 v2 規格第 31 節的準4+、準5+、標準／完整、共用計算與防爆案例。
- 新增完整歷史資料超過 30、80、100 期時仍可找到合法 occurrence 的案例。
- 驗證 13 來源期只建一次、拖牌不建 range cells、加減／合值共用 range cells、標準／完整不共用最終結果。
- 驗證輸出排序、規則數、預測號碼去重與驗證資料契約。

- 天衍與天工的演算法規則。
