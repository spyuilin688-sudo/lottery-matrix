# 樂彩 Matrix 功能頁響應式收斂設計

日期：2026-08-22

## 目標

在不新增、刪除或改變既有功能流程的前提下，統一歷史開獎紀錄、號碼對照單、Matrix 同星、通知與我的頁面的密度、外距、頁首操作與響應式來源，並修正同星期數顯示格式。

## 核准範圍

### 歷史開獎紀錄

- 將所有使用者可見的「篩選條件」改為「篩選設定」。
- 標題卡操作按鈕的圖示、外框與文字整體縮小 10%，並相對目前位置向下 4px。
- 標題卡與操作按鈕使用同一個 sticky 頁首容器；內容捲動時保持可見，但不得以獨立 fixed 元素遮住清單。
- 開獎資訊列表左右外距固定為共用 12px 頁面外距。

### 號碼對照單

- 「刷新」與「探索設定」共用歷史頁「篩選設定」的按鈕高度、圓角、邊框、圖示與文字規格。
- 「探索設定」對齊標題卡右下方；「刷新」位於其左側，兩者間距 6px。
- 頁面內容使用共用 12px 左右外距。
- 縮減列表表頭、資料列高度、期數欄寬、字級與單元格留白；保留可辨識的彩種號碼、標記列與標記單格互動。
- 不使用 transform 縮放整張表格，也不使用固定畫布寬度或水平裁切。

### Matrix 同星

- 在標題卡右下方新增與歷史頁相同規格的「探索設定」按鈕。
- 既有彩種、排序、號碼與期數設定移入可收合面板；收合時保留目前設定值，不重設資料。
- 標題卡與探索設定按鈕使用 sticky 頁首容器。
- 移除 Matrix 同星頁的「近10期開獎號碼」資訊卡，不影響 API 呼叫與探索結果。
- 頁面使用共用 12px 左右外距。
- 同星結果的所有期數統一經過彩種期數正規化，不針對單一期數寫死。現有異常格式為「2～3 位年度／批次前綴 + `000` + 3 位流水號」；移除中間補位後，前綴補足 3 位，再與 3 位流水號組成正式 6 碼期數。例如 `96000024 → 096024`，同格式的其他期數全部依同一規則修正。正規化只影響前端資料標準化與顯示，不修改 API 原始資料或資料庫。

### 快捷、通知、我的頁首

- 三個底部導覽頁共用首頁 `matrixya.png`。
- Logo 的寬度、置中方式與上下位置只由同一組首頁品牌變數／共用類別控制。
- 不用負 margin、transform 位移或頁面專屬 `!important` 修正。

### 通知頁 Product Design 優化

- 保留八種通知、設定 Dialog、開關與既有文案及順序。
- 降低卡片、圖示、標題、Matrix Pro 標籤、設定按鈕及列間距的視覺尺寸，提高首屏可見資訊量。
- 視覺控制縮小，但開關與按鈕的實際點擊區維持行動裝置可操作尺寸。
- Dialog 同步降低垂直密度，避免選項被截斷或需要不必要的長距離捲動。

### 我的頁 Product Design 優化

- 保留會員卡、訂閱資訊、功能選單與全部既有入口。
- 縮減會員卡、頭像、登出按鈕、訂閱資訊卡、選單標題與列高。
- 以字重、顏色及間距維持層級，不用放大卡片製造強弱。
- 最後一張卡片與底部導覽保留共用安全區避讓。

## 共用響應式架構

- `--layout-page-inline: 12px` 為功能頁唯一左右外距來源。
- 元件內部 padding 不視為頁面外距；不能用 `width: calc(100% - 24px)` 再加 12px margin 造成雙重縮排。
- 標題卡 sticky 容器需有明確背景與堆疊層級，且只在頁面自己的捲動容器內生效。
- 保留底部導覽安全區與彩球尺寸等必要專用規則；清理重複固定寬高、補償性位移、負 margin、跨頁 `!important` 與後置覆寫。
- 320px 至 430px 寬度不得出現水平溢出；內容在 Pixel 10 基準下完整，iPhone 寬度同步適配。

## 資料與狀態

- 所有收合狀態使用 React state；開啟或關閉設定不清除使用者輸入。
- 同星期數格式由彩種感知的純函式處理並單獨測試。函式同時支援 8 位與 9 位的舊格式，輸出正式 6 碼期數；已是 6 碼或不符合已知舊格式的值原樣保留，避免誤改六合彩、天天樂或其他正常期數。
- 不修改爬蟲、後端 API、資料庫結構或歷史資料。

## 測試與驗收

- 先加入會失敗的需求回歸測試，再修改 production code。
- 驗證歷史頁文案、按鈕縮放與位移、sticky 頁首、12px 外距。
- 驗證號碼對照單兩按鈕順序、6px 間距、共用按鈕規格與緊湊列表。
- 驗證 Matrix 同星設定可收合、近10期卡片不存在，並以多筆 8 位／9 位異常期數、正常 6 碼期數與不符合格式的值測試通用正規化規則；其中至少包含 `96000024 → 096024`。
- 驗證快捷、通知、我的 Logo 共用首頁來源。
- 驗證通知與我的頁不存在重複固定高度、負位移與水平溢出規則。
- 執行需求測試、相關既有測試、TypeScript、production Vite build 與 runtime integrity check。
