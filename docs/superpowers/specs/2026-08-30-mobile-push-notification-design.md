# 手機推播第一階段設計規格

日期：2026-08-30  
專案：樂彩 Matrix  
範圍：手機推播訂閱、管理後臺測試發送、發送紀錄

## 1. 目標

完成一條可實際驗證的手機推播流程：

1. 使用者以既有 LINE 登入。
2. 使用者在手機上主動開啟通知。
3. 系統保存該手機的推播訂閱。
4. 管理員在獨立管理後臺選擇單一會員並發送測試通知。
5. 使用者手機收到通知。
6. 管理後臺保存成功或失敗結果。

## 2. 已確認需求

- 維持 LINE 登入，不增加另一套使用者登入。
- 推播訂閱資料存放於 Supabase。
- 測試推播按鈕放在管理後臺「通知管理」。
- 測試通知採固定內容：
  - 標題：樂彩 Matrix 測試通知
  - 內容：手機推播已成功啟用
- 管理員必須先選擇會員，才能發送測試通知。
- 第一階段只完成訂閱、單一會員測試發送、手機接收及結果紀錄。
- 第一階段不串接開獎、付款、會員到期等自動通知。

## 3. 使用者端流程

1. 使用者完成 LINE 登入。
2. 使用者點擊既有的手機通知開關或「開啟手機通知」操作。
3. 手機顯示通知權限詢問。
4. 使用者允許後，系統建立該手機的推播訂閱並保存至 Supabase。
5. 畫面顯示通知已開啟。
6. 使用者關閉通知時，停用該手機的訂閱。

通知權限只能由使用者主動操作時提出，不在頁面載入時自動彈出。

## 4. 管理後臺流程

「通知管理」頁面增加測試推播操作：

1. 選擇一名會員。
2. 顯示該會員暱稱、LINE 頭貼及推播啟用狀態。
3. 未選會員或會員沒有有效訂閱時，禁止發送。
4. 點擊「發送測試推播」。
5. 使用固定標題與內容發送至該會員已啟用的手機。
6. 顯示發送成功或失敗。
7. 保存本次發送紀錄。

第一階段不提供全體會員群發，也不提供自訂測試文字。

## 5. 資料設計

### 5.1 手機推播訂閱

每一筆資料代表一名會員的一支手機，保存：

- 會員識別
- 推播端點
- 推播加密所需資料
- 是否啟用
- 建立時間
- 更新時間
- 最後成功時間
- 最後失敗時間

同一會員可以有多筆手機訂閱。停用其中一筆不影響其他手機。

### 5.2 推播發送紀錄

每次測試發送保存：

- 會員識別
- 發送時間
- 固定通知標題
- 固定通知內容
- 發送結果
- 失敗原因
- 執行發送的管理員

發送結果表示系統是否成功送交推播服務，不代表使用者已閱讀。

## 6. 系統分工

- PWA：詢問手機通知權限、建立或停用手機訂閱、接收並顯示通知。
- Supabase：保存手機訂閱與發送紀錄，限制會員只能管理自己的訂閱。
- 管理後臺：選擇會員、發送測試推播、查看發送結果。
- 伺服器端發送程式：使用保存在伺服器端的推播金鑰發送通知，不把私密金鑰放入 PWA。

## 7. 權限與限制

- 使用者只能新增、查看、更新或停用自己的推播訂閱。
- 管理後臺沿用既有管理員權限。
- 推播私密金鑰只存在伺服器端。
- 管理員每次只能對一名已選會員發送測試通知。
- 失效的手機訂閱在發送失敗後標記停用。

## 8. 失敗處理

- 使用者拒絕通知權限：不建立訂閱，畫面維持未開啟狀態。
- 手機不支援推播：不建立訂閱，顯示無法開啟。
- 訂閱保存失敗：顯示開啟失敗，不顯示為已啟用。
- 會員沒有有效訂閱：管理後臺禁止發送。
- 部分手機成功、部分失敗：逐筆保存結果；失效訂閱標記停用。
- 發送程式失敗：管理後臺顯示失敗並保存原因。

## 9. 驗收條件

1. LINE 登入會員可在實際手機上主動開啟通知。
2. Supabase 可查到該會員與該手機的有效訂閱。
3. 管理員可在「通知管理」選擇該會員。
4. 管理員可發送固定測試通知。
5. 實際手機可收到「樂彩 Matrix 測試通知」。
6. 點擊通知可開啟樂彩 Matrix PWA。
7. 管理後臺可查到發送時間、結果及失敗原因。
8. 關閉通知後，該手機不再收到後續測試通知。
9. 不影響既有 LINE 登入、會員資料與通知設定保存功能。

## 10. 第一階段不包含

- 開獎自動通知
- 付款通知
- 續訂或到期通知
- Matrix 狀態通知
- 全體會員群發
- 自訂通知內容
- 已讀追蹤
- AppDeploy 使用者登入
