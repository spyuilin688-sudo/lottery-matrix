# Matrix security monitoring

User-approved scope: suspicious request records, grouped administrator push alerts, configurable API/login limits, and Cloudflare configuration verification. Public queries start in observation mode; enforcement needs real usage evidence. No visual redesign, membership/algorithm changes, merge, deployment, or live database writes in this implementation phase.

## Architecture and preserved behavior
- Add a private Supabase security policy/counter/event store and a service-role-only RPC for Railway/admin observations. Bound input length, route cardinality, persistence, and alert frequency. Never store request bodies, passwords, cookies, credentials, or tokens. Prefer hashed source identities; notification text must not contain IPs or member identifiers.
- Keep the six existing Matrix query RPC names/arguments/results/ACLs. Move their unchanged implementations to private; public VOLATILE wrappers preserve JWT-based original authorization and query semantics. Use a fixed allowlist, no dynamic caller-supplied function identifiers. Original ACLs: Explore list/validation anon+authenticated+service_role; Tianyan/Tiangong list/validation authenticated+service_role only. Private originals/helper cannot be invoked by client roles.
- PostgREST failures raised before a wrapper (invalid JWT, malformed JSON, ACL denial) remain platform-log-only. Do not claim to detect all crawlers or all attacks. Expected business errors are caught inside a subtransaction, recorded outside it, and returned with response.status and original PostgREST code/message/details/hint. Do not RAISE the final mapped response because that rolls back the record. SQL calls with no request.method preserve original exception semantics. GET/HEAD wrappers reject without writes; current PWA calls POST. Unknown internal failures retain server errors/platform logging.
- Public wrappers are read-only at the business-data level; only telemetry is written. Existing algorithm source and entitlement checks are preserved unchanged. If future migrations replace query bodies, they must target private originals or reapply wrappers.
- Extend/reuse the current admin Web Push infrastructure, preserving transfer behavior. Security jobs use separate event IDs, lease/retry/eligibility guards, expired-subscription handling, and deduplication. Only active superadmins with enabled existing admin push endpoints receive alerts. Continue using the existing dispatch token/VAPID configuration, with no new secret values in code. No test push to a real user during development.
- Railway uses bounded asynchronous observation for normal queries, bounded-time synchronous policy checks only when enforcement is explicitly configured. Unknown/forwarded IP headers must not be trusted blindly; document proxy trust. Admin login records failed attempts outside the legacy activity-log exemption; malformed/unauthorized routes may be observed without changing successful login behavior. Do not change the existing superadmin ordinary activity logging rule.
- Observability dependency failure must not stall normal queries or weaken existing auth; bounded timeout and sanitized degradation logging. Limit mode is observe by default; explicit enforce returns 429 with Retry-After and must not run the protected business operation.

## Proposed reviewable operational defaults
These are implementation defaults for review, not measured production thresholds: public query alert threshold 120 requests / 60 seconds; admin login attempts and unauthorized requests 10 / 300 seconds; all modes observe. Group notifications for the same source/category for 15 minutes. Retain telemetry/counters/finished jobs for 7 days using bounded cleanup. Keep policy values server-controlled and validate ranges. No permanent blocking.
