# Matrix 天工生產候選產生器設計

日期：2026-08-21

分支：`api`

狀態：使用者已確認，進入實作計畫

## 1. 目標

補齊現有 Matrix 天工純評估器與 API 之間缺少的生產候選產生器。最新開獎同步後，後端須以完整歷史資料自動建立天工結果，與 Matrix 探索、天衍使用同一分析版本發布；PWA 只篩選已完成結果，不執行演算法。

## 2. 正式時間座標

- 歷史資料為由新到舊排列，最新一期是來源位置 `1`。
- 來源位置以一為起點；位置 `p` 對應 `history[p - 1]`。
- 等距來源序列的來源間距為 `d`。`d` 只決定 A／B／C／D 來源期如何排列，不決定任何一段的結果期。
- 一段式第一段下 `n1` 期；來源位置 `p` 的結果位置為 `p - n1`。
- 二段式第一段下 `n1` 期至中間結果，再由中間結果下 `n2` 期至最終結果；相對原始來源的最終結果位置為 `p - (n1 + n2)`。
- 來源間距 `d`、第一段期距 `n1`、第二段期距 `n2` 是三個獨立搜尋維度。
- 對 A 來源位置 `a`，一段式預測期距為 `n1 - a + 1`；二段式預測期距為 `n1 + n2 - a + 1`。只有預測期距大於 `0` 的候選才是未來預測。
- 預測結果期可以是下 N 期，不固定為下一個未開獎期。
- 第一段與第二段的下 `N` 期搜尋上限取決於候選要預測的結果期；任何階段端點超過該預測結果期都沒有意義，不列舉。

一段式已確認案例：來源 `114215`、`114222`、`114229` 的來源間距 `d = 7`，第一段均下 `n1 = 5` 期，結果分別為 `114220`、`114227`、`114234`。因此來源間距與結果期距彼此獨立。

二段式已確認案例：來源 `114212`、`114216`、`114220` 的來源間距 `d = 4`；第一段均下 `n1 = 9` 期至 `114221`、`114225`、`114229`，第二段再下 `n2 = 5` 期至 `114226`、`114230`、`114234`。此例 `n1 + n2 = 14`，與 `d = 4` 無等式關係。

## 3. A／B／C／D 與命中條件

來源序列由新到舊命名為 A、B、C、D：

- 命中條件統一表示為 `準N進N+1`：建立 N+1 個等距來源組，回推驗證 N 次，第 N+1 組產生預測。
- `準2進3`：建立 3 組，回推驗證 2 次，第 3 組產生預測。
- `準3進4`：建立 4 組，回推驗證 3 次，第 4 組產生預測。
- 一段式以前 N 組使用相同完整規則驗證命中，第 N+1 組套用相同完整規則產生預測。
- 二段式第一段的相同中間規則須在 N+1 組成立；第二段以前 N 組使用相同完整規則回推驗證命中，第 N+1 組套用相同第二段規則產生最終預測。
- 二段式第 N+1 組的第一段中間結果成立，不計入最終命中次數；其第二段結果才是預測。
- 同一階段要求的組別必須使用相同完整規則；中間任何一組失敗，該階段規則不成立。

以 `3、6、9` 為例：

1. `3、6、9` 只表示三個來源的來源間距 `d = 3`。
2. 二段式第一段以同一組 `n1` 與同一完整規則驗證 C、B、A，三組都成立才保留。
3. 第二段以同一組 `n2` 與同一完整規則驗證 C、B。
4. 將相同第二段規則套用 A 產生最終預測；結果期由 `n1 + n2` 決定，不由 `d` 決定。

## 4. 等距來源序列

- 五十期與八十期分別建立所有完整落在範圍內的合法序列。
- 序列須滿足相鄰位置差完全相同。
- `準2進3` 列舉三項序列；`準3進4` 列舉四項序列。
- 探索期數五十期／八十期用於限制來源資料及合法等距來源組合範圍。
- 五十期：來源等距組合必須完整落在五十期內。
- 八十期：來源等距組合必須完整落在八十期內。
- 若探索範圍為 `H`、來源序列長度為 `L`、A 來源位置為 `a`，合法來源間距須滿足 `a + (L - 1) × d <= H`。
- 來源序列是否合法，只依其是否完整落在所選的五十期或八十期來源資料範圍內判定。
- 第一段、第二段的下 N 期搜尋不以五十期／八十期作為上限；搜尋上限由預測結果期決定，超過預測結果期的組合不搜尋、不驗證。
- 八十期完整產物可依序列最大位置判定是否同時符合五十期篩選，不重複計算相同規則。

## 5. 搜尋範圍

對每個驗證來源搜尋第一段參照期：

- 上 1～14 期：來源位置 `p + 1` 至 `p + 14`。
- 當期：來源位置 `p`。
- 下 1 期至最終結果期前一期；上限由該候選的獨立結果期距決定，而不是來源間距 `d`。
- 一段式最終結果位置 `p - n1`、二段式最終結果位置 `p - (n1 + n2)` 均不得成為參照期。
- 超出已取得歷史資料的參照期直接排除，不得用其他期數替代。

同一候選的所有來源組必須使用完全相同的參照位移。

## 6. 球位方向

探索球位、第一段球位、第二段球位各自獨立列舉：固定、依序遞增、依序遞減。

方向一律由最舊驗證組走向最新驗證組，再走到 A 預測組：

- `準2進3`：C → B → A。
- `準3進4`：D → C → B → A。

每條路徑不得越過彩種合法球位。今彩539、天天樂使用 5 個球位；六合彩、大樂透使用 6 個正碼球位加特別號，共 7 個球位。

- 探索球位決定各來源／參照資料取用的基礎球位。
- 第一段球位決定第一段結果球位。
- 第二段球位只在二段式使用，決定最終結果球位。

## 7. 一段式

一段式資料流：`參照資料 → 第一段運算 → 預測結果期`。

對 `準N進N+1`：

1. 前 N 組依共同參照位移、探索球位、第一段期距 `n1`、第一段球位、演算法和值進行驗證。
2. 前 N 組必須使用相同完整規則並全部命中。
3. 第 N+1 組套用相同完整規則產生預測。

`準2進3`：前 2 組驗證命中，第 3 組產生預測。`準3進4`：前 3 組驗證命中，第 4 組產生預測。

一段式的 `n1` 獨立搜尋。第 N+1 組套用相同 `n1` 後必須落在允許的預測結果期內；超過該預測結果期的 `n1` 不搜尋。

## 8. 二段式

二段式資料流：`參照資料 → 第一段 → 第二段 → 結果期`。

- 第一段期距 `n1` 與第二段期距 `n2` 各自獨立列舉，兩者皆為正整數。
- `n1`、`n2` 各自搜尋，搜尋上限由預測結果期決定。
- 第一段端點與第二段最終端點都不得超過該候選的預測結果期；超過者不搜尋。
- 第一段以參照資料為基礎，在第一段球位取得／驗證中間結果。
- 第二段只能以前一段取得的號碼作為起點，再以第二段共同演算法與共同值產生最終結果。
- 對 `準N進N+1`，第一段相同中間規則必須在 N+1 組成立；此處不是 N+1 次最終命中。
- 第一段 N+1 組成立後，才以全部第一段結果搜尋第二段規則。
- 第二段以前 N 組已有結果回推驗證 N 次；全部成立後，將相同第二段規則套用第 N+1 組的第一段結果產生最終預測。
- 不得要求第 N+1 組的第二段結果已命中，因為該結果就是本次預測。

## 9. 版路運算

- 加減候選值沿用正式範圍 `-49..+49`；`+0` 固定分類為拖牌。
- 合值候選值沿用正式範圍 `1..98`。
- 所有運算依彩種循環：今彩539、天天樂為 `1..39`；六合彩、大樂透為 `1..49`。
- 合值公式為 `normalize(合值 - 基礎號碼)`。
- 加減公式為 `normalize(基礎號碼 + 加減值)`。
- 不得因循環後結果相同而把非零加減值改名為拖牌；拖牌身分只屬於 `+0`。

版路名稱：

- 一段式：加減版路、合值版路、拖牌版路。
- 二段式相同類型合併為單一名稱；不同類型顯示「第一段＋第二段」。

## 10. 規則身分、去重與排序

完整規則身分包含：

- 探索期數資格、來源序列、來源間距 `d`、模式、命中條件。
- 探索球位方向與起始球位。
- 參照位移。
- 第一段期距、球位方向、起始球位、演算法和值。
- 二段式的第二段期距、球位方向、起始球位、演算法和值。

只有完整規則身分、預測期距、預測位置、預測號碼與版路類型全部相同時才去重。相同預測由不同完整規則產生時分開保留。

結果依下列順序穩定排序：

1. 間距由小到大。
2. 預測期距由小到大。
3. 預測位置由小到大。
4. 版路類型。
5. 穩定 ID。

## 11. 驗證資料

每個結果清單不內嵌大型驗證資料；驗證內容以 `itemId` 分離保存。二段式 `準N進N+1` 的資料角色必須拆分為：

- 第一段中間結果成立：N+1 組，不計為 N+1 次最終命中。
- 第二段驗證：前 N 組，共回推驗證 N 次。
- 最終預測：第 N+1 組套用第二段規則所得結果。

每個第一段成立組與第二段驗證組至少保存：

- 組名、來源位置、來源期數與完整開獎號碼。
- 參照位移、參照期數、參照球位、基礎號碼。
- 第一段期距、球位、演算法、值、計算結果與實際命中號碼。
- 若該組屬於第二段驗證，保存第二段同等資料。
- 最終結果期、結果球位、完整開獎號碼與是否命中。

第 N+1 組須同時保存已成立的第一段證據，以及第二段的預測來源、預測期距、預測位置、計算過程與預測號碼。其第一段標記為成立證據；第二段標記為 prediction，不列入第二段已命中組數。

## 12. 生產管線與可讀版本

最新開獎完成後：

1. 讀取完整歷史。
2. 建立 Explore artifact。
3. 建立 Tianyan artifact。
4. 建立 Tiangong artifact。
5. 三者都成功建立後才開始發布。
6. 依序寫入 Explore、Tianyan、Tiangong。
7. 最後寫入同版本完成標記，`artifactKinds` 必須包含 `explore`、`tianyan`、`tiangong`。

任何一項建立或發布失敗時，不更新完成標記；API 繼續讀取上一個完整版本。

## 13. API 與 PWA 相容性

- 天工 API 沿用既有方案權限、清單、篩選與驗證詳情端點。
- API 列表新增正式 `sourceSequence` 與 `predictionDistance`；移除錯誤限定三項的內部 `sourceTriple` 假設。
- PWA 仍顯示間距期數、預測位置、預測、版路類型；不顯示近 10 期或連準篩選。
- 一段式不送出、不篩選第二段設定；二段式才使用第二段條件。

## 14. 效能設計

- 先將四彩種歷史資料轉為球位陣列，避免候選內重複排序。
- 以「來源序列＋方向路徑＋參照位移＋獨立段落期距」建立驗證轉換。
- 第一段先用第一組已知的來源號碼與第一段結果號碼，直接反推出可能的加減值與合值，不逐一測試全部加減值與合值。
- 將第一組反推的候選規則依序交由後續組驗證並淘汰不成立者；只有第一段 N+1 組的相同中間規則都成立時才可保留。
- 第一段成立後，才以 N+1 組第一段結果搜尋第二段；第二段同樣先由第一組反推可能規則，再由後續 N-1 組交叉驗證。
- 第二段前 N 組成立後，才將相同規則套用第 N+1 組產生預測。
- 不得將全部加減值、合值、球位走法與期距建立無條件笛卡兒積後全面暴力搜尋。
- 結果與驗證資料以穩定簽章串流去重，避免先建立重複大型物件。

## 15. 測試與驗收

測試必須先失敗再實作，涵蓋：

- 三項／四項合法等距來源序列；最大來源間距只受 50／80 期探索範圍限制。
- `d = 7、n1 = 5`：`114215/114222/114229` 分別對應 `114220/114227/114234`，證明一段式結果期距不等於來源間距。
- `d = 4、n1 = 9、n2 = 5`：`114212/114216/114220` 經第一段至 `114221/114225/114229`，再至 `114226/114230/114234`，驗證三個期距維度可獨立成立。
- 第 N+1 組是否能產生預測，由 `n1` 或 `n1 + n2` 是否落在預測結果期內判定。
- 一段式通用規則：`準N進N+1` 的前 N 組使用相同完整規則驗證命中，第 N+1 組產生預測。
- 二段式通用規則：第一段 N+1 組的相同中間規則成立，但不計為最終命中；第二段回推驗證前 N 組共 N 次，第 N+1 組用於產生預測。
- 五十期／八十期只限制來源資料及合法等距來源組合；第一段、第二段下 N 期的上限由預測結果期決定。
- 上 1～14、當期、下 1～結果前一期，且結果期不可作參照。
- 固定、遞增、遞減的合法與越界球位。
- 一段式獨立搜尋 `n1`；二段式獨立搜尋 `n1`、`n2`；各階段不得越過預測結果期。
- 第一段由第一組反推候選規則，再以其餘 N 組交叉驗證；第二段由第一組反推、其餘 N-1 組驗證、第 N+1 組預測。
- 加減、合值、`+0` 拖牌與四彩種循環。
- 同結果不同規則保留，完全相同結果去重。
- 驗證資料與清單分離。
- Tiangong 加入完成版本標記；失敗時保留上一個完整版本。
- 既有天工 PWA 篩選、方案權限與驗證詳情行為不退化。
