## 1. 目標

新增「Matrix 天衡」演算法與頁面。除本文件列出的差異外，演算法規則、探索設定、結果互動、展開驗證、視覺間距、排列、字型、大小、選項與尺寸全部比照「Matrix 探索」。

天衡與探索的核心差異是：每個來源條件固定鎖定兩個開獎位置及其號碼。

## 2. 鎖定條件

以一期開獎號碼 `10、15、16、18、20` 為例，依位置順序建立所有不重複的兩兩組合：

1. 第一顆 10＋第二顆 15
2. 第一顆 10＋第三顆 16
3. 第一顆 10＋第四顆 18
4. 第一顆 10＋第五顆 20
5. 第二顆 15＋第三顆 16
6. 第二顆 15＋第四顆 18
7. 第二顆 15＋第五顆 20
8. 第三顆 16＋第四顆 18
9. 第三顆 16＋第五顆 20
10. 第四顆 18＋第五顆 20

每組鎖定條件包含：

- 靠前鎖定位置與號碼
- 靠後鎖定位置與號碼
- 來源期數
- 來源期索引

每個彩種沿用 Matrix 探索目前支援的全部開獎位置。鎖定組合固定按位置先後排列，不建立反向重複組合。

## 3. 回推與版路規則

### 3.1 共通規則

「天衡加減」、「天衡合值」、「天衡拖牌」皆使用同一組雙鎖定條件回推及驗證。歷史組必須同時符合相同的兩個位置及兩個號碼，不能只符合其中一個。

探索範圍、號碼排序、探索日期、預測間距、標準範圍、完整範圍、循環號碼計算、規則命中及驗證方式均沿用 Matrix 探索。來源當期的探索範圍排除該組兩個鎖定位置。

### 3.2 天衡拖牌

天衡拖牌使用靠前的鎖定條件本身作為同期計算位置。拖牌規則值仍由 Matrix 探索既有回推方式取得，不直接把兩個鎖定號碼當成規則值。

顯示範例：

第一列：

`開 05 第 1 顆｜同期｜第 1 顆`

第二列：

`開 18 第 4 顆｜+XX.XX｜下 X 期開`

其中 `XX.XX` 代表回推取得的規則值。

### 3.3 加減與合值摘要

版路摘要固定為兩列，版面比照 Matrix 天衍。排列結構為：

- 第一列：靠前鎖定條件｜參照期距｜參照位置
- 第二列：靠後鎖定條件｜規則值｜預測間距

第二列不沿用 Matrix 天衍的縮排鎖定內容排列。

## 4. 連準篩選

天衡的來源條件始終是雙鎖定條件。「鎖定1碼／鎖定2碼」沿用 Matrix 探索的規則數量意義。

### 準5+（鎖定1碼）

- 準5進6
- 準6進7
- 準7進8
- 準9進10

### 準7+（鎖定2碼）

- 準6進7
- 準7進8
- 準9進10
- 準11進12

只有以上層級可成為天衡結果；其他連準次數不輸出。

## 5. 探索設定與權限

天衡的探索設定全部比照 Matrix 探索，只修改探索期數：

- 三期
- 十三期

三期的存取行為完全比照 Matrix 探索二期，供未訂閱會員使用。十三期沿用 Matrix 探索十三期的訂閱權限。其他設定及權限判斷不變。

背景分析一次計算最多十三期來源條件。使用者切換三期或十三期時，只篩選已儲存結果，不重新執行演算法。

## 7. 驗證過程

「版路🔻」展開後沿用 Matrix 探索驗證結構：

- 左側期數
- 中間開獎號碼
- 右側驗證式
- 歷史驗證組
- 當前來源組
- 結果號碼
- 內容保護與展開互動

每個歷史驗證組標示同一組雙鎖定條件。加減、合值、拖牌均使用結果列所屬的同一組雙鎖定條件驗證。

## 8. 後端分析架構

採用獨立天衡結果、共用同一次 Matrix 分析任務的方案。

同一次開獎分析流程：

1. 載入並整理一次歷史開獎資料。
2. 執行 Matrix 探索既有階段。
3. 執行獨立的 `tianheng` 階段。
4. 天衡按來源期及雙鎖定組合分批計算。
5. 產生天衡成品並寫入獨立結果資料表。
6. 所有必要階段完成後，分析任務才標記完成。

天衡重用探索的號碼排序、候選值計算、循環加減、合值、範圍及驗證資料結構；雙鎀定索引、雙鎖定回推及天衡連準層級由天衡模組負責。

Matrix 狀態的既有計算來源不因新增天衡而改變。

## 9. Supabase 資料與 RPC

新增：

- 天衡分析成品種類：`tianheng`
- 天衡獨立結果資料表：`matrix_tianheng_results`
- 列表 RPC：`matrix_tianheng_list(jsonb)`
- 驗證 RPC：`matrix_tianheng_validation(jsonb)`

天衡結果資料至少保存：

- 彩種、開獎期數、分析版本
- 結果 ID
- 兩個鎖定位置與兩個鎖定號碼
- 來源期索引與來源期數
- 預測間距
- 連準層級與最高連準
- 預測號碼
- 版路類型
- 號碼排序
- 規則數量
- 探索範圍
- 結果及驗證 JSON
- 到期時間

列表 RPC 支援與天衡頁面對應的期數、日期、範圍、排序、版路、連準、同碼及預測號碼篩選。驗證 RPC 按結果 ID 讀取同版本驗證資料。

公開 RPC 沿用目前 Matrix RPC 的請求防護、錯誤回傳與權限控制；三期存取行為比照探索二期，十三期比照探索十三期。

## 10. 錯誤處理

沿用 Matrix 探索既有狀態與呈現：

- 請求內容無效
- 無可用分析結果
- 分析尚未完成
- 分析版本不一致
- 需要登入
- 權限不足
- 請求競態時只採用最新回應

新增天衡不得改變探索、天衍、天工及 Matrix 狀態既有錯誤行為。

## 11. 測試與驗收

只執行與天衡直接相關的測試，不執行全專案測試。

### 演算法

- 五顆號碼產生十組且無反向重複的雙鎖定條件。
- 歷史回推必須同時符合兩個位置與兩個號碼。
- 加減、合值、拖牌使用同一組雙鎖定條件。
- 拖牌使用靠前鎖定條件的同期位置。
- 連準結果只輸出指定層級。
- 三期及十三期以來源期索引正確篩選。
- 各彩種號碼上限、排序及位置規則沿用探索。

### 分析與資料

- 天衡在同一分析任務中以獨立階段執行。
- 分批中斷後可依既有分析機制續跑。
- 天衡成品及正規化結果一致。
- 列表與驗證 RPC 使用相同開獎期數及分析版本。
- 三期與十三期權限符合規格。
- 公開 RPC 權限與請求防護符合既有 Matrix 模式。

### 前端

- 新路由及四個 Matrix 頁面切換正確。
- 使用指定標題卡與切換圖示。
- 天衡只顯示三期及十三期。
- 連準選項文字及值完全符合規格。
- 結果呈現兩個鎖定位置及號碼。
- 摘要固定兩列且第二列順序正確。
- 展開驗證使用同一雙鎖定條件。
- 兩套詞綴隨獨立切換開關同步切換。
- 390px 手機基準與 Matrix 探索版面一致。

## 12. 不變更範圍

除頁面切換入口與同一次分析流程整合外，不修改 Matrix 探索、Matrix 天衍、Matrix 天工及 Matrix 狀態的既有演算法、篩選條件、結果內容或權限。
