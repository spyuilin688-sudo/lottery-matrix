# 樂彩 Matrix－探索功能三版路演算法 API 完整修正版規格

版本：2026-09-01 修正版  
適用：Matrix 探索／Matrix 狀態共用演算法核心  
版路：加減版路、合值版路、拖牌版路  
狀態：**規格已整理；尚未以完整真實歷史資料實測驗證，不得標記為已通過。**

---

## 1. 本版已確認修正

1. **完整歷史資料不設 8／12／80 期上限。**
   - 準4+ 的「8」、準5+ 的「12」是單條版路用來確認是否超過合法最長連準的回推驗證邊界，不是歷史資料總量限制。
2. **準5+ 第二個共同值沒有固定出現位置。**
   - 不一定在 D、E 出現。
   - B、C、D、E 可以都只有第一共同值延續，到 F、G、H……才出現第二共同值。
   - 只要仍存在合法候選路徑，就不能因某一期沒有第二值而停止。
3. **標準範圍與完整範圍不重算兩次。**
   - 底層只建立一次完整範圍基礎資料。
   - 標準範圍由同一批基礎資料過濾掉上8～14期。
   - 但兩種範圍的共同值、連準與最終有效性仍要依各自候選集合重新判定。
4. **拖牌與加減／合值使用不同驗證資料。**
   - 拖牌：只使用鎖定條件本身。
   - 加減／合值：使用範圍資料，且排除鎖定條件本身。
   - 加減與合值可共用同一份完整範圍 cell。
5. **相同鎖定條件的歷史 occurrence 只搜尋一次。**
   - 找到 B、C、D、E……後，再分流給拖牌與加減／合值各自建候選。
6. **相同最長連準若超過2個可延續值，整條無效。**
   - 必須等整條候選各自延續到不能延續後再判斷。
   - 不可在中途暫時看到3個候選值就淘汰。
   - 不得把3個值拆成兩兩組合輸出。
7. **超過最大合法連準時整條無效，不得截短。**
8. **中間候選不寫入最終結果；完整驗證後才輸出。**

## 2. A、B、C、D 定義

對某個正在探索的鎖定條件：

- `A`：目前來源鎖定條件／預測組。
- `B`：歷史上最近一次相同鎖定條件。
- `C`：再前一次。
- `D`、`E`、`F`……：依時間由近到遠繼續回推。

歷史搜尋必須從最近往前搜尋**完整歷史資料**，不得用最近80期、100期等固定資料窗取代。

---

## 3. 探索來源期只建立一次

探索期數：

- 二期
- 七期
- 十三期

正確底層做法：

```text
一次建立13個來源期
↓
完成基礎計算
↓
每筆記錄 lockedSourceIndex
↓
查詢時依來源期位置篩選
├─ 二期
├─ 七期
└─ 十三期
```

不能為二期、七期、十三期各自重跑完整演算法。

### 十三期鎖定條件數量

- 今彩539：5×13=65；順球／落球分別建立。
- 天天樂：5×13=65；只使用依號碼由小到大排序。
- 六合彩：7×13=91；順球／落球分別建立。
- 大樂透：7×13=91；順球／落球分別建立。

---

## 4. 排序方式

- 依號碼由小到大排序（順球）。
- 依實際開獎順序排序（落球）。
- 天天樂只使用順球。

同一條版路歷史比對不可跨排序模式混算。

---

## 5. 驗證範圍

### 5.1 標準範圍（加減／合值）

```text
上1～7期
+
同期合法位置
+
下1期～預測／結果期前1期
```

### 5.2 完整範圍（加減／合值）

```text
上1～14期
+
同期合法位置
+
下1期～預測／結果期前1期
```

結果期本身不得列入驗證範圍。

例：預測下2期，只納入下1期。  
例：預測下10期，納入下1～9期。

### 5.3 鎖定條件本身

**加減／合值：**排除鎖定條件本身。  
**拖牌：**驗證資料就是鎖定條件本身。

---

## 6. 標準／完整只做一次基礎計算

每個歷史 occurrence 只建立一次完整 range cells：

```text
上14 ... 上8 ... 上7 ... 上1
同期其他合法位置
下1 ... 預測／結果期前1
```

每個 cell 記錄至少：

```text
period
relativeOffset
position
number
scopeClass
```

`scopeClass`：

```text
STANDARD_AND_FULL
FULL_ONLY
```

建議分類：

- 上1～7、同期合法位置、合法下方位置 → `STANDARD_AND_FULL`
- 上8～14 → `FULL_ONLY`

同一份 cell 同時計算：

```text
├─ 加減候選
└─ 合值候選
```

然後：

```text
完整範圍 = 全部 cell
標準範圍 = 過濾 FULL_ONLY
```

### 重要

不能把「完整範圍最後已形成的版路結果」直接刪掉上8～14證據後當標準結果。

正確做法是：

```text
基礎 cell／候選只算一次
↓
標準／完整各自取得可用候選集合
↓
各自做共同值、最長延續、連準與有效性判定
```

## 7. 三版路共用 occurrence，但候選 builder 分開

```text
A
↓
一次搜尋完整歷史相同鎖定條件
↓
B、C、D、E、F...
↓
分流
```

### 7.1 拖牌

每個 occurrence 只取鎖定位置本身：

```text
B → B locked cell
C → C locked cell
D → D locked cell
...
```

不建立完整 range cells。

### 7.2 加減＋合值

每個 occurrence：

```text
建立完整範圍 cell
↓
排除鎖定條件本身
↓
同一 cell 同時計算
├─ 加減
└─ 合值
```

所以禁止：

```text
拖牌重新掃歷史一次
加減再掃一次
合值再掃一次
```

正確：

```text
occurrence index 共用
↓
├─ DragCandidateBuilder
└─ FullRangeCellBuilder
   ├─ AddCandidateCalculator
   └─ SumCandidateCalculator
```

## 8. 加減版路

採循環制。

### 今彩539／天天樂

```text
+1～+39
```

### 六合彩／大樂透

```text
+1～+49
```

摘要與公式一律以正向 `+` 顯示：

- 39碼彩種：`-1 = +38`
- 49碼彩種：`-1 = +48`

### +0

目前已確認：

```text
+0 可以用於加減版路
+0 也可以用於拖牌版路
```

## 9. 合值版路

合值呈現完整值：

- 今彩539／天天樂：1～78。
- 六合彩／大樂透：1～98。

例如：

```text
合值25.40
合值45.67
合值43.70
```

預測號碼則轉回正式合法號碼。

---

## 10. 拖牌版路

拖牌核心：

```text
驗證資料 = 歷史相同鎖定條件本身
```

不使用上1～14、同期其他位置、下方範圍。

`+0` 可作為拖牌有效值；同時也可作為加減版路有效值。

---

## 11. 準4+（鎖定1碼）

最終只需要1條共同規則。

### 11.1 起始

```text
B → 候選池
C → 候選池
↓
B ∩ C
```

若無共同值：

```text
STOP
```

若有共同值：

```text
固定共同值
↓
D → E → F...
↓
持續找真正最長延續
```

### 11.2 有效輸出

```text
準4進5
準5進6
準6進7
準7進8
```

### 11.3 最大邊界

最高有效為：

```text
準7進8
```

若實際還能延續成準8進9或更長：

```text
整條 INVALID
```

不得刪掉最早一次後偽裝成準7進8。

### 11.4 「最多8」的真正意思

不是只讀8期歷史，也不是只保留8筆歷史資料。

而是：

```text
單一版路最多驗證到足以確認
是否已經在第8次仍然延續
```

一旦確認超過最大合法連準，該路徑即可判無效停止。

---

## 12. 準5+（鎖定2碼）

最終必須有：

```text
恰好2條不同規則／共同值
```

禁止3條以上規則。

兩條不同規則可得到：

- 2個不同預測號碼；或
- 同1個預測號碼。

若預測同碼：準5+仍有效，結果欄去重後只顯示1碼。

---

## 13. 準5+ 候選狀態機

### 13.1 B、C 先產生候選

```text
B candidates
C candidates
↓
B ∩ C
```

### 13.2 B、C 沒共同值

不能像準4+一樣停止。

```text
B候選 + C候選
↓
最多10個候選值
↓
往D比對
```

若與 D 完全不存在任何仍可合法延續關係，才停止該候選路徑。

若形成第一共同值，進入「第一共同值已確定」狀態。

---

## 14. 第一共同值確定後

假設第一共同值：

```text
+10
```

不能只保留 `+10`，必須維護：

```text
已確定第一共同值
+
仍有資格成為第二共同值的候選集合
```

原始候選結構：

```text
第一共同值確定前：最多10個候選
第一共同值確定後：1個已確定共同值 + 另一側5個候選
```

---

## 15. 第二共同值沒有固定出現位置

這是關鍵修正。

錯誤：

```text
D沒有第二值 → STOP
```

錯誤：

```text
E一定要形成第二值
```

正確：

```text
第一共同值可單獨延續多個 occurrence
第二共同值可在任何後續合法 occurrence 才形成
```

例如：

```text
B：+10
C：+10
D：+10
E：+10
F：+10、+24
```

則：

```text
第一共同值 = +10
第二共同值 = +24（到F才形成）
```

只要仍存在能形成有效鎖定2碼版路的候選路徑，就必須繼續往前。

---

## 16. 第二共同值確定後

例如：

```text
共同值1 = +10
共同值2 = +24
```

此後：

- 固定兩條規則完成剩餘最長延續驗證。
- 不再重新展開新的 pair 組合。
- 確認是否超過最大合法連準。
- 完整延續結束後，再做相同最長連準值數量判定。

---

## 17. 同一驗證組有2值只算1次連準

例如 F 同時：

```text
+10 成立
+24 成立
```

F 仍只算：

```text
1次連準
```

不能因同一驗證組命中2值就讓連準 +2。

---

## 18. 準5+ 有效輸出與最大邊界

允許呈現：

```text
準5進6
準6進7
準7進8
準9進10
準11進12
```

最高有效：

```text
準11進12
```

若實際延續成準12進13或更長：

```text
整條 INVALID
```

不得截短偽裝成準11進12。

「最多12」指：

```text
驗證到足以確認是否已經在第12次仍延續
```

不是歷史資料只讀12期。

---

## 19. 準5+ 單次值位置限制

若其中一條值在整段連準中只佔1次：

```text
不能只在頭
不能只在尾
只能在中間
```

此限制用於避免將長共同值與端點上的其他候選錯誤配對，形成大量假版路。

---

## 20. 相同最長連準 >2 值

適用三種版路：

- 加減
- 合值
- 拖牌

必須先讓候選各自：

```text
延續到不能延續
↓
取得真正最長連準
```

再判斷。

例如：

```text
+10 = 準7進8
+15 = 準7進8
+20 = 準7進8
```

則：

```text
整條 INVALID
```

不得輸出：

```text
+10.+15
+10.+20
+15.+20
```

### 判定時機

錯誤：回推途中暫時看到3個候選就淘汰。  
正確：完整延續後，比較真正的相同最長連準。

---

## 21. 三版路共用連準核心

三版路的候選值產生方式不同，但候選產生後共用核心：

```text
候選產生
↓
B、C、D、E...逐次往前
↓
完整延續
↓
取得真正最長連準
↓
檢查
├─ 最低合法連準
├─ 最大合法連準
├─ 相同最長值數量
├─ 鎖定1碼／鎖定2碼規則數
└─ 準5+單次值頭尾限制
↓
有效才輸出
```

## 22. 早停規則

### 準4+

可早停：

1. B、C 無共同值。
2. 唯一共同值已斷且不存在其他合法路徑。
3. 已確認超過準7進8 → `INVALID`。

### 準5+

**不能**因某一期沒有第二共同值就停止。

真正可停止：

1. 所有仍可能形成恰好2條有效共同值的候選路徑都已斷。
2. 已確認超過準11進12 → `INVALID`。
3. 完整延續後不符合最終合法性 → `INVALID`。

---

## 23. 去重規則

### 23.1 候選值去重

同一候選池相同值先去重再進狀態機。

### 23.2 準4+

最終只能輸出：

```text
1條規則
```

### 23.3 準5+

最終只能輸出：

```text
恰好2條不同規則
```

舊的「至少3條規則覆蓋全部驗證組」不得採用。

### 23.4 預測號碼去重

兩條規則預測同一碼時：

- 邏輯仍是鎖定2碼。
- 顯示只輸出1個預測號碼。

### 23.5 禁止同長最長值兩兩組合

相同最長值 >2：整條無效，不做 `n choose 2`。

## 24. API 防爆邊界

以下屬工程保護，不得改變演算法結果。

### 24.1 不限制完整歷史總量

禁止以固定80／100／N期代替完整歷史。

### 24.2 最大連準早停

- 準4+：驗證至足以確認是否超過準7進8。
- 準5+：驗證至足以確認是否超過準11進12。

### 24.3 中間候選不落最終資料表

只有完整合法性驗證通過後才寫 final result。

### 24.4 禁止笛卡兒積

不得先展開：

```text
所有occurrence
× 所有cell
× 所有候選值
× 所有共同值
× 所有pair
```

再過濾。

應使用：

- occurrence index
- Set／bitset
- intersection
- incremental state
- early stop
- lazy evaluation

### 24.5 occurrence 索引

建議 key：

```text
lottery
sortMode
position
number
```

A 出現後直接取得 B、C、D、E……，避免每個 A 都重新掃完整歷史。

### 24.6 完整 range cells 快取

同一 occurrence 的完整範圍資料只建立一次，可同時供：

- 加減
- 合值
- 標準 filter
- 完整範圍

### 24.7 拖牌不建 range cells

拖牌只讀 locked cell。

## 27. 結果呈現

主要欄位：

- 位置
- 號碼
- 預測期
- 連準次數
- 預測
- 版路類型

摘要例：

```text
開 02 第1顆 | 上8期 | 第4顆 | +34 | 下2期開
```

準5+兩值：數值小的在前，以點號分隔：

```text
+8.17
+0.30
+3.39
+2.4
```

不得：

```text
+17.8
+30.0
+8+17
```

預測兩碼也由小到大；兩規則預測同碼只顯示一次。

## 28. 結果排序

優先序：

```text
連準次數 > 預測期 > 位置
```

連準由高到低，例如：

```text
準11進12 > 準9進10 > ... > 準5進6
```

預測期由近到遠：

```text
下1期 > 下2期 > ... > 下13期
```

位置由前到後。

## 29. 驗證資料顯示

- 左欄：期數。
- 中欄：該期完整開獎號碼。
- 右欄：驗證公式與實際驗證期對齊。
- 兩條驗證公式若分屬不同驗證期，上下各一列。
- 預測結果對準預測列。
- 拖牌若同一驗證期有兩條公式，可增加一列，左／中欄空白，右欄放第二條公式。


```text
準5+只讀最近12期
```

```text
完整歷史只讀80期
```

```text
準5+第二共同值必須在D或E出現
```

```text
第一共同值確定後，下一期沒第二值就STOP
```

```text
標準範圍完整重算一次，完整範圍再重算一次
```

```text
拖牌也建立上1～14完整範圍
```


## 32. 最終核心原則

```text
完整歷史可搜尋
↓
13來源期只建一次
↓
相同鎖定條件 occurrence 只找一次
↓
拖牌與加減／合值分流
↓
加減＋合值完整範圍只建一次
↓
標準由完整基礎資料篩選
↓
準4+／準5+使用各自正確狀態機
↓
候選完整延續到不能延續
↓
再判斷真正最長連準與>2值
↓
合法才去重、格式化、輸出
```

核心防錯：

> 限制的是單條版路的候選狀態、合法最長連準、規則數與輸出，不是限制完整歷史資料量。

> 準5+ 第二共同值沒有固定出現期數，只要仍存在合法候選路徑就必須繼續往前驗證。

> 標準／完整、二／七／十三期應共用可共用的底層一次性計算，但最終有效性判定不可混在一起。

> 拖牌只使用鎖定條件本身；加減／合值使用範圍驗證，兩種驗證資料不得混用。
