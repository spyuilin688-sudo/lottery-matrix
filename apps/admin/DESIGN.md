# 營運後台設計

## Overview

服務手機與桌面的管理員，快速查閱營運資料、會員、訂閱及轉帳。沿用深色金色識別，重點是掃讀與明確操作；不使用行銷式大卡片或滿版操作按鈕。此文件只管理 apps/admin，前台 PWA 仍由根目錄 DESIGN.md 管理。

## Colors

背景 #090b0f、卡片 #111419、邊界 #30333a、重點 #e1c170、正文 #ece7d8。成功與錯誤仍有文字及語意狀態。

## Typography

Inter、Noto Sans TC、system-ui；資料與次要資訊 12–13px，區段標題 15–17px、統計數值 22px。長資料可換行，表格保留橫向捲動查看完整欄位。

## Layout

手機內容左右各 10px，桌面 14px。統計卡最小高度 60px，以內容自然長高。營運概覽前四張為流量／會員、後四張為訂閱；分隔線 1px，兩側垂直間距各 8px（同一 grid 的 row-gap）。手機兩欄、桌面四欄；收入卡保留原有分組。

用戶管理、訂閱管理、登入紀錄、審計日誌保留共用搜尋卡片：搜尋、狀態／方案與筆數集中在同一列，不顯示日期或排序控制。其他管理頁只保留本身必要工具，不重複建立共用搜尋卡片；伺服器端資料讀取、搜尋防抖、預設排序與底部分頁維持既有契約。頁面工具列主要動作高 30px、表單確認動作至少 32px、一般行內操作 28–32px、標題列觸控目標至少 40px；頁面工具列、表單卡片與一般區塊採 8px 節奏。按鈕依文字寬度，不強制手機整列。

## Elevation & Depth

以邊界和低強度陰影區分區塊。對話框沿用既有焦點、確認與遮罩行為。

## Shapes

卡片圓角 10–12px，控制 8px；不新增裝飾性形狀。

## Components

Runtime ownership（Model B）：src/admin.css 單獨擁有基本排版、共用密度與 primary／loginPrimary／formActions 按鈕幾何；src/admin-operations.css 擁有管理清單的專屬結構；src/profile-name.css 擁有姓名對話框與 modal 捲動；src/system-status.css、src/admin-transfer-push.css、src/admin-todos.css 擁有各自元件。CSS 為來源，本文件是鏡像。

手機通知使用預設收合的原生 details / summary，一行顯示通知狀態，展開才顯示說明與設定動作；收合不改變裝置註冊。權限、註冊、停用、付款金額及確認／拒絕 API 不因排版而改變。轉帳狀態僅將既有值翻成繁體中文。

「權限切換」沿用緊湊後台工作區，最大寬度 720px。兩個設定各自以標題、影響說明及原生 `role="switch"` 控制組成；所有管理員看到相同伺服器狀態，非超級管理員的控制保持 disabled 並有文字說明。修改使用既有 `ConfirmationDialog`，頁內保留 loading、status、alert 與重試。760px 以下讓文字與控制自然換成單欄，不截斷說明，開關觸控區至少 44px。此功能不新增全域色彩、字型或形狀 token。

權限切換在控制列上方常駐顯示目前 PWA 的「訂閱購買」與「會員免費使用」狀態、最近成功檢查時間及「每小時自動檢查」提示。每 60 分鐘重新讀取同一伺服器端權威設定；背景讀取失敗保留最近成功狀態並顯示錯誤，不猜測或覆蓋值。

## Do / Don't

使用自然高度與可收縮欄位，保留可操作焦點、錯誤及空狀態。不要以固定高度裁切內容、改變權限或把預覽資料帶入正式站。

### 系統設定服務檢查

系統設定主畫面以營運處理需求為第一層，不再把技術驗證層級當成主狀態。頁首先顯示「目前沒有需要處理的異常」或需要處理的項目數，並統計「正常／等待／無需處理／需處理」四種狀態；其下的「需要處理」區只列真正需要人工查看的項目。API 已確認但刻意未執行會員登入、寫入、通知或復原流程時顯示「無需處理」，正常等待開獎、排程、執行完成或驗證樣本時顯示「等待」，實際失敗、資料不足以判定、Warning／Critical 才顯示「需處理」。

每項服務以獨立邊框分隔，間距 8px。名稱、用途、營運狀態與是否需要處理的原因常駐；API 位址、時間、回應代碼、技術驗證結果、驗證方式及排程明細全部收在「查看技術明細」原生 details，預設收合且鍵盤可操作。技術證據仍完整保留，區分實際查詢、正式資料、Endpoint 連線、所屬服務、正式執行紀錄、會員流程未執行與寫入操作未執行。文案由 src/system-status.ts 與 backend/api-status-inventory.ts 擁有，既有檢查、功能、操作權限與安全限制保持一致；不得為了讓狀態變成正常而執行會寫入正式資料、派送通知、登出會員或啟動復原的操作。

通知派送健康以事件式正式架構為準：驗證 notification_events 的事件觸發器、管理員轉帳觸發器、通知 queue 的動態 Recovery replan triggers、依最早 retry／lease 時間建立的 `matrix-notification-recovery-next`，以及每小時一次的 `matrix-notification-recovery-fallback` 保底。沒有待補救工作時不保留動態 job；Web／Native／Admin 三類待處理、逾時與 24 小時正式派送結果仍分開顯示。健康檢查本身不得送出測試通知；服務商接受紀錄不得描述成裝置一定顯示。

Railway 操作由 src/RailwayOperations.tsx 與 src/system-status.css 擁有，使用既有原生彩種選單、compactButton 與 AdminApp 確認對話框。手動更新與復原沿用管理員 edit 權限，一次選定一個彩種，送出期間鎖定操作，失敗不自動重送。復原回應 accepted 只顯示已受理，不能描述成已完成；already-running 顯示未重複啟動。操作回饋使用持續可見的 status／alert 區域。

### 代辦、通知與 Railway 操作密度

代辦工作區最大 680px；composer 不顯示重複的共用／編輯說明與新增欄位標籤，但保留可存取名稱。新增輸入區最小高 104px；composer 與代辦清單之間使用 1px 分隔線，分隔線上下各 12px。留言維持單一清單的分隔列，桌面操作靠右、窄版移至內容下方。通知工作區最大 960px；卡片共用標題，收件對象與固定內容桌面雙欄、手機單欄；頭像 32px，發送說明與按鈕並列；發送紀錄每頁 5 筆並沿用共用分頁。這三個工作區的行內動作為 28px 高、12px 字級、依內容寬度。

Railway 原生彩種選單固定 104px 寬、28px 高、12px 字級；兩種操作各自一列，常駐用途及適用時機，按鈕靠右。復原說明明列天天樂僅分析、背景受理不等於完成，以及重新檢查與避免重複送出的方式。保留既有確認、權限、狀態回饋與 API 行為。

### 會員資訊視窗

用戶管理與訂閱管理共用 src/UserInfoDialog.tsx；採原生 modal dialog，瀏覽器管理焦點限制與 Escape，關閉後還原觸發按鈕焦點。src/member-info.css 擁有 620px 最大寬度、12px 內距、兩卡 8px 間距、28px 動作與每頁五筆登入紀錄。第一卡保留會員名稱、登入身分、註冊時間與最後上線時間，並依目前資料列補上既有帳號狀態、最近連線 IP、推估地區，以及訂閱頁既有方案／開始／到期／自動續訂資訊；不顯示會員內部 ID。標籤欄以 92px 對齊；窄版標籤欄 84px、卡片內距 10px，IP 與登入身分可斷行。表格失敗保留重試，切換會員清除先前資料，換頁期間停用動作。用戶列表以狀態欄承載原有停權／啟動操作，不額外增加操作欄。

登入紀錄取自驗證服務的工作階段，重新整理及權杖續期不新增登入。最近連線 IP 代表最近驗證連線；既有工作階段的原始登入 IP 不可還原，顯示尚未記錄。IP 地區由後台 IPWhois HTTPS API 估算，只傳 IP，不傳帳號／名稱／權杖；成功結果快取七日，失敗一小時，每次最多查十個新 IP，服務失效顯示無法判定。會員紀錄隨帳號刪除而移除。會員及訪客不可讀取，後台沿用來源模組的查看權限。

### 訂閱、付款與管理清單

訂閱管理頁頂以「訂閱會員／付款紀錄／轉帳申請」三分頁切換功能；手機單列三等寬、44px 高的深底金色選取按鈕，桌面沿用相同行為，內容自然延伸。通知連結 `#transfer-requests` 選中轉帳分頁。訂閱會員分頁只列出未到期、啟用中且方案天數為 30／90／365 的成功訂閱會員；月費、季費、年費直接排列在同一張表，不切換清單。會員名稱與 LINE ID／Google ID 分欄顯示，沿用同一筆會員資料。訂閱會員保留共用搜尋卡片，單列包含搜尋、狀態、方案與筆數；用戶管理、登入紀錄、審計日誌沿用相同層級。付款紀錄與轉帳申請保留各自的搜尋與資料分頁，切換功能分頁時保留各自篩選與頁碼。表格內「調整到期日」與「用戶資訊」按鈕高 24px、11px 字級。付款紀錄與沖銷維持原生 details 卡片，進入付款分頁時展開；summary 顯示標題與筆數。每筆紀錄以明確分隔線區隔；已確認狀態使用金色標籤，並與高 24px、10px 字級的「記錄沖銷」按鈕並排於右側，不建立多餘空白列。僅超級管理員且具訂閱編輯權限者可操作沖銷；確認視窗說明方案與效期同步重算，若目前權益無法由付款重現則顯示衝突而不更新資料。

付款紀錄的時間標籤依來源區分：人工轉帳的既有 `paid_at` 來自會員送出回報時寫入的 `transferred_at`，顯示「回報時間」；綠界付款保留「付款時間」。兩者都不描述成銀行核對入帳時間或管理員審核時間。

用戶管理每頁 15 筆，訂閱會員每頁 30 筆，由 backend/admin-data.ts 的既有分頁設定控制查詢筆數與頁碼。主選單的登入紀錄每頁 10 筆，顯示登入時間、登出時間、IP、推估地區與裝置資訊，不顯示「本次在線時間」；IP 後緊接推估地區欄；啟動碼管理每頁 10 筆，換頁時清除本頁勾選，避免跨頁誤複製或誤刪。會員資訊視窗內的登入紀錄仍維持既有每頁 5 筆契約。

### 架構總彙

`src/ArchitectureOverview.tsx` 與 `src/architecture-overview.css` 擁有四平台訂閱總覽。沿用 systemSettings 查看權限、共用 panel／compactButton 及原生 details／summary；四平台預設收合，名稱、方案、方案費用、下次付款日期及本次應繳常駐；付款金額下方附人工核對日期，避免與每日自動更新混淆。桌面單列三欄對齊，760px 以下改為名稱／方案一列、日期／金額一列，標題觸控區至少 100px、自然高度可換行。使用既有黑金配色，不新增全域 token、圖片或裝飾。

展開後分為付款說明、費用組成、額度與用量、最近帳單／付款紀錄；長來源與更新資訊再收於原生 details。費用與帳務明細的標籤、值及附註依文字自然同行排列，不設固定標籤欄寬或強制附註另起一行；超出可用寬度才自然換行，維持原字級。額度保留來源單位，分列包含額度／上限、已用、剩餘及重置時間；付費用量上限由項目名稱與說明明確區分，不視為免費額度，不推算百分比或把未知當零。管理訂閱連結保留另開分頁與安全 rel。所有展開動作只操作已讀取資料，不新增 API、輪詢或權限。

資料取自受保護的 `admin_architecture_subscriptions` 已核實紀錄，僅在開啟頁面時讀取。GitHub 與 Railway 由 Supabase 每日 09:20（Asia/Taipei）同步一次；同日重複觸發不再呼叫平台，單一平台失敗保留其原快照與確認時間。Supabase 與 Cloudflare Pages 尚未具備完整自動帳務來源，保留原資料。讀取失敗顯示錯誤與重試；StrictMode 重複掛載沿用同次請求，卸載後不更新已關閉頁面。平台帳務資料不打包於前端，也不記錄信用卡或登入憑證。

`billing_snapshot.account` 是官方帳務頁人工核對快照，包含付款日期及說明、付款金額及狀態、費用、額度、來源及原核對時間；缺少 account 的既有紀錄仍相容。共用 reader 明確白名單處理巢狀欄位，限制每列字串 200 字及費用／額度各 30 列，拒絕格式不符的快照。人工核對時間常駐於展開的付款說明，不與每日帳務更新混為一談。

主列只採 account 明確核對的付款日期／金額；預估標為「預估應繳」、未結帳標為「待出帳」，未知標為「尚未確認」，展開後說明原因。不得以方案費用、續費紀錄、上次付款日、帳務週期或公開定價推算扣款日期／金額。既有 billing 保留最近帳單／付款、本期累計、預估、期間與原來源；用量、折抵與實付分開呈現，不把折抵前用量預估稱為最終應繳。每日同步不代表歷史付款重新核對，原人工付款核對說明完整保留於來源。

GitHub 已有本期用量時，摘要標示「用量資料已取得」，不將付款欄位未知誤報為串接失敗。Cloudflare 尚無本期用量及帳戶明細時標示「Pages 帳務未取得」，展開付款說明直接呈現已記錄的 API 讀取結果與阻擋原因。顯示這些狀態只使用原有單次資料讀取，不在開頁或展開時執行平台檢查。

### 後台 PWA 身分

後台 manifest 的 `id`、`start_url`、`scope` 都固定為 `/admin/`，啟動時註冊 `/admin/admin-push-sw.js` 並限制 scope 為 `/admin/`。管理後台與前台 PWA 保持不同安裝身分及服務工作者範圍。

### 後台啟動畫面（2026-09-12）

只保留 Android PWA 系統原生的黑底圖示啟動階段，不增加網頁啟動遮罩、直式圖片、播放計時器或 inert 鎖定，避免兩段啟動畫面。index.html 保留載入前的純黑背景，React 直接呈現登入頁或後台。PWA、apple-touch 與推播圖示只使用使用者指定的方形 1000020222.png，等比例縮為 180／192／512px 的 admin-icon-20260912-*；禁止從直式啟動圖產生安裝圖示。安裝身分與推播 scope 維持 /admin/。

### Matrix Storage 儲存健康

系統設定沿用既有 Supabase 服務檢查群組，新增一項 Matrix Storage。`statusRows`、`statusFacts` 與原生 details 維持既有密度、焦點與重新檢查流程；資料庫實際大小及 Healthy／Warning／Critical 常駐，明細提供探索、天衡、成品、分塊大小、版本列數與清理紀錄。大小採十進位 MB／GB，數字為 zh-TW，日期沿用 Asia/Taipei；未提供方案容量時不顯示使用率。

健康判定只依管理員後端取得的儲存健康回報，不把 API 連線或四彩種查詢當成儲存健康證據。主畫面將 Healthy 顯示為「正常」，Warning／Critical 顯示為「需處理」；原始 Healthy／Warning／Critical 保留在技術明細。缺漏或無效資料屬「需處理」，資料庫大小仍可取得時繼續常駐顯示；無清理時間顯示尚無紀錄。重新檢查失敗保留先前內容及展開狀態並顯示錯誤。清理狀態明列排程開關與最近錯誤，不新增手動清理動作或另一個狀態頁。

### Matrix 資料鏈

系統設定沿用服務檢查的狀態列、statusFacts、原生 details 與 system-status.css。四彩以自然高度、窄版單欄顯示同一期各階段；文字區分已驗證、異常、等待與證據不足。恢復 accepted 只顯示等待驗證。過期觀察的總狀態改為待重新確認，保留最近證據。Inspector 及 Optimizer 為只讀資訊，未增加權限或自動修改動作。

監控的新鮮度由 `backend/watchdog-status.ts` 統一判定。排程待命須有近期資料庫排程紀錄；保留的資料鏈標示「上次」並保留原檢查時間，不算本次重新驗證。應執行未完成或排程自身超過 18 分鐘未更新仍標示異常。通過的資料鏈不顯示故障未定位文案。

Inspector 的執行證據依明確 outcome 分類：未取得、未到期與無新資料顯示 WAITING；未知 outcome 顯示 UNKNOWN，不視為成功。排程階段說明直接取自 Watchdog 的實際階段設定。

### 管理員編輯與共用確認

管理員編輯使用讀取時的 revision；伺服器以相同 revision 條件原子更新，資料已變更則回傳衝突，不恢復舊狀態或權限。衝突保留草稿並提示取消編輯、重新載入後再試；不得自動以新版 revision 重送舊表單。最後一位啟用中超級管理員的既有保護保持生效。

`AdminApp.tsx` 的共用 `ConfirmationDialog` 沿用 `UserInfoDialog` 的原生 modal dialog：瀏覽器限制焦點並隔離背景，開啟時聚焦取消，Escape 等同取消且不送出操作，關閉後還原原觸發控制焦點。`admin-operations.css` 擁有原有 420px 最大寬度、遮罩與可捲動的視窗內高度，不改變既有確認文案或動作。

通知收件人沿用原生 select 與共用分頁，每頁最多 30 位；以繁體中文姓名／登入身分搜尋，300ms 防抖、輸入法組字完成後才查詢、Enter 立即查詢、清除立即更新並返回輸入焦點。換頁及搜尋保留明確選定的收件人，不自動改選；發送後只重新查核該收件人的有效訂閱與最新紀錄。搜尋及收件選擇是此單次發送工作階段的暫存狀態，不寫入網址，以免將會員姓名／登入身分保存於瀏覽紀錄。

### 平台付款總覽

每平台只保留一張卡片，付款資料與詳細資料合併。付款日期、剩餘天數、目前累計、本次應付、待出帳及預估採左標籤右數值，金額說明另行小字；未知值為灰色，已知金額為金色。費用、額度、付款紀錄等明細使用原生 details 分區收合；來源與核對日期集中於來源區。architecture-overview.css 擁有此頁可收縮兩欄與自然換行，不使用固定高度、截字或橫向捲動。台灣日曆倒數只用一個共用時鐘，維持午夜及返回頁面更新，不新增資料請求。

### 2026-09-26 清單讀取效率

`use-admin-data-page.ts` 共用清單只對非空搜尋文字變更套用 300ms 防抖；換頁、篩選及清除立即讀取。換查詢與卸載取消過期 GET，保留請求版本防覆寫；取消不顯示載入錯誤，不影響任何寫入操作。會員列表的身分、連線及近三日在線時間獨立並行讀取，在線秒數由資料庫按當頁會員彙總，維持既有時間邊界與分鐘取整。
