## Test 9 - Railway 彩種操作與取消
Viewport: mobile (375x667)
Covers: Railway manual refresh, selected lottery, confirmation cancellation, POST /api/system-status/:id/refresh
Description: 使用既有授權且有編輯權限的管理員工作階段；不建立帳號或更動權限。
Steps:
1. 開啟系統設定，於 Railway 操作選擇今彩539。
2. 點擊手動更新，確認對話框顯示今彩539，先按取消，確認未送出更新。
3. 再次點擊手動更新並確認；等待結果，期間不可重複送出或切換彩種。
Expected: 回應成功時顯示伺服器回傳期數；失敗則有可見原因，不顯示成功。375px 畫面選單及兩個操作按鈕可用且無水平溢出。沒有編輯權限的既有帳號不可操作。

## Test 4 - 啟動碼多選複製、兌換暱稱與刪除限制
Viewport: desktop (1280x800) and mobile (375x667)
Covers: GET /api/data/activationCodes, multi-row selection, clipboard output, members.line_display_name, redeemed-code delete permission
Description: 使用已有授權管理員工作階段進行唯讀驗證；不建立或刪除啟動碼。若目前不足兩組啟動碼，明確回報資料前置條件不足，不建立測試資料。
Steps:
1. 以已有營運管理員工作階段開啟「啟動碼管理」。
2. 確認已兌換碼的「兌換會員」欄顯示 LINE 暱稱，而非會員 UUID。
3. 點擊「選取」，勾選目前列表中的兩組啟動碼，再點擊「複製」。
4. 檢查複製成功訊息與剪貼簿內容。
5. 比較未兌換碼與已兌換碼的刪除操作；再以已有超級管理員工作階段查看已兌換碼。
Expected: 選取模式顯示逐列核取方塊；複製內容依列表順序以換行分隔，畫面顯示已複製數量；營運管理員可刪除未兌換碼，但已兌換碼按鈕停用並顯示「已兌換，僅超級管理員可刪除」；超級管理員的已兌換碼刪除按鈕可用。全程不確認任何刪除。

## Test 6 - 系統設定服務狀態、明細與異常
Viewport: desktop (1280x800) and mobile (375x667)
Covers: GET /api/system-status, compact status badges, readable probe evidence, native details, per-function HTTP errors
Description: 只使用已有授權管理員工作階段唯讀檢查；沒有工作階段則回報無法執行，不建立帳號或修改權限。
Steps:
1. 開啟系統設定，確認各服務以獨立邊框及 8px 間距分隔。
2. 查看「API 已建立」「連線正常」「主機正常」及檢查說明；藍色部分檢查不等於已驗證完整功能，標籤約 20px 高。
3. 展開、收合「檢查明細」，查看 API 位址、時間及回應代碼；收合時用途、檢查範圍與錯誤訊息仍可見。
4. 點擊「重新檢查」，確認資料更新。卡片、最新開獎、歷史開獎、同星、號碼對照單、探索清單與探索展開資料各自查詢四彩種；全部成功才顯示綠色「查詢正常」。
5. 查詢失敗時顯示彩種及錯誤；探索無樣本時顯示藍色「缺少測試資料」。會員身分與會修改資料的操作清楚說明限制。查看 Pilio 開獎通知的連線檢查結果。
Expected: 狀態文字清楚、小型標籤不擠壓名稱；失敗維持紅色並顯示該 API 的錯誤原因。Pilio 接受不執行通知工作的 OPTIONS 檢查，回應 204；這只代表連線有回應，不代表已派送通知。展開與重新檢查不觸發資料更新、兌換、發送通知或變更排程。

## Test 7 - 後台清單完整性與權限
Viewport: mobile (375x667)
Covers: GET /api/data/:table, GET /api/dashboard, pagination and existing session guard
Description: 使用已有授權管理員工作階段讀取現有資料，不建立大量測試資料。成功登入後的過期 session 清理屬內部維護，1500ms 上限已由單元測試覆蓋，不以正式帳號反覆登入測試。
Steps:

Expected: 既有清單、搜尋與分頁可用；資料足夠時能找到 200 筆以後的紀錄；不修改會員、付款或任何清單資料。

## Test 8 - 超級管理員手機轉帳通知入口與權限
Viewport: mobile (375x667)
Covers: GET/POST/DELETE /api/admin-transfer-push, superadmin-only device enrollment, permission boundary, #transfer-requests navigation
Description: 僅使用既有管理員工作階段檢查；沒有帳號則回報無法執行，不建立帳號或轉帳申請，不發送測試通知、不替使用者允許通知權限。
Steps:
1. 以已有超級管理員工作階段開啟訂閱管理，查看轉帳申請的手機通知區塊。
2. 確認初始狀態來自伺服器，不會自動跳出通知權限要求；不支援的瀏覽器顯示說明。
3. 若可操作，按啟用並取消通知權限要求。
4. 開啟後台 #transfer-requests，確認登入後到達訂閱管理。
5. 使用既有一般管理員工作階段查看相同頁面；無工作階段時確認 API 不提供裝置資料。
Expected: 超級管理員可見手機通知控制，預設只顯示一行「手機通知」與目前狀態，點擊可展開／收合，展開後才顯示說明及設定按鈕；展開本身不會啟用或停用通知，按鈕高度約 32px、依內容寬度；取消權限不顯示啟用成功；一般管理員不可見控制且不能操作 API；通知連結導向轉帳申請。POST/DELETE 裝置儲存與停用、後端派送及重試已由相關單元與交易回滾測試驗證，正式手機送達需使用者本人啟用後確認。
