# Tests

## Test 1 - 管理員登入並修改自己的名稱 [sanity]
Viewport: desktop
Covers: AppDeploy Auth, GET /api/bootstrap, PUT /api/me/name, Supabase admin_accounts, audit_logs
Description: 驗證啟用中的管理員可登入並修改自己的名稱，重新整理後仍保留修改結果。

Steps:
1. 使用已存在於 admin_accounts 且狀態為啟用的管理員帳號登入
2. 點擊右上角自己的管理員名稱
3. 輸入新的名稱並儲存
4. 重新整理頁面

Expected: 右上角顯示新的管理員名稱，重新整理後名稱仍維持不變。

## Test 2 - 手機版搜尋會員並停用或啟用
Viewport: mobile
Covers: GET /api/data/users, PUT /api/members/:id/status, member search/filter, mobile member cards, audit_logs
Description: 驗證營運管理員可在手機版搜尋會員、查看會員資料並切換帳號狀態。

Steps:
1. 以營運管理員進入「用戶管理」
2. 使用會員 ID、方案、推薦碼或邀請碼搜尋一位會員
3. 使用狀態選項篩選會員
4. 點擊會員卡片中的「停用會員」或「啟用會員」

Expected: 會員卡片顯示驗證用戶 ID、LINE 用戶 ID、方案、到期日、推薦碼、邀請碼及最新帳號狀態。

## Test 3 - 手動管理會員訂閱
Viewport: desktop
Covers: GET /api/data/subscriptions, GET /api/data/plans, PUT /api/subscriptions/:id, activate, renew, cancel, adjustExpiry, lifetime
Description: 驗證營運管理員可依現有方案手動開通、續訂、取消續訂、調整到期日或設定終生會員。

Steps:
1. 以營運管理員進入「訂閱管理」
2. 選擇一位會員並執行開通或續訂，選擇方案後確認
3. 再執行「取消續訂」
4. 重新載入「訂閱管理」

Expected: 方案與到期日依操作更新；取消續訂後自動續訂顯示「否」，原到期日仍保留。

## Test 4 - 審核轉帳申請並套用角色統一權限
Viewport: desktop
Covers: GET /api/data/transferRequests, PUT /api/transfer-requests/:id, payments linkage, role module permissions, last-super and self-delete protection
Description: 驗證營運管理員可確認或拒絕待審核轉帳，查看人員只能查看，管理員保護規則不允許刪除自己或移除最後一位啟用中的超級管理員。

Steps:
1. 以營運管理員進入「訂閱管理」的「轉帳申請」
2. 對待審核申請點擊「確認」或「拒絕」
3. 以查看人員重新登入並開啟相同頁面
4. 以超級管理員進入「管理員權限」並檢查自己的刪除操作

Expected: 確認的申請建立付款並開通方案，拒絕的申請不建立付款；查看人員沒有異動按鈕；系統拒絕刪除自己及移除最後一位啟用中的超級管理員。

## Test 5 - 系統連線狀態獨立呈現異常
Viewport: mobile
Covers: GET /api/system-status, AppDeploy status, Supabase Database/Auth, Matrix status APIs, four lottery cron statuses, fault isolation
Description: 驗證進入系統設定會自動檢查所有項目，並可手動重新檢查；單一 API 異常不會清除其他項目的狀態。

QA Faults:
```json
[
  {
    "method": "GET",
    "path": "/api/system-status",
    "status": 200,
    "body_json": {
      "checkedAt": "2026-08-21T03:00:00.000Z",
      "items": [
        { "id": "matrix-audit-api", "name": "Matrix audit API", "description": "檢查開獎資料是否缺期、重複或異常。", "ok": false, "checkedAt": "2026-08-21T03:00:00.000Z", "responseMs": 120, "error": "HTTP 500" },
        { "id": "matrix-coverage-api", "name": "Matrix coverage API", "description": "檢查四個彩種的資料涵蓋範圍與筆數。", "ok": true, "checkedAt": "2026-08-21T03:00:00.000Z", "responseMs": 80 }
      ]
    }
  }
]
```

Steps:
1. 進入「系統設定」
2. 查看連線狀態卡片
3. 點擊「重新檢查」

Expected: Matrix audit API 顯示異常及錯誤內容，Matrix coverage API 仍顯示正常；每張卡片顯示項目說明、最後檢查時間及回應時間。
