# Tests

## Test 1 - 未登入時不可讀取營運統計 [sanity]
Viewport: mobile (375x667)
Covers: GET /api/dashboard, existing admin session guard
Description: 唯讀驗證；不得建立帳號、修改會員、調整權限、重設收入或發送通知。
Steps:
1. 開啟後台但不登入。
2. 嘗試讀取 /api/dashboard。
Expected: 顯示既有登入畫面，dashboard 不回傳統計資料。

## Test 2 - 營運概覽瀏覽人數
Viewport: mobile (375x667)
Covers: GET /api/dashboard, todayVisitors, monthVisitors, totalVisitors, existing member counts
Description: 僅使用已有授權管理員工作階段進行唯讀驗證；若沒有帳號或工作階段，回報無法執行，不建立資料。
Steps:
1. 以已有管理員工作階段開啟營運概覽。
2. 比對 dashboard 回應與本日瀏覽人數、本月瀏覽人數、總瀏覽人數卡片。
3. 重新整理營運概覽。
Expected: 三張卡顯示伺服器人數，總用戶数等原卡片保留；手機畫面沒有橫向溢出或文字碰撞；不修改任何會員或付款資料。

## Test 3 - 統計讀取失敗提示
Viewport: desktop (1280x800)
Covers: GET /api/dashboard failure, existing dashboard error state
Description: 僅驗證讀取與畫面，禁止任何寫入操作。
QA Faults:
```json
[{"method":"GET","path":"/api/dashboard","status":503,"body_json":{"error":"統計讀取失敗"}}]
```
Steps:
1. 使用已有授權管理員工作階段開啟營運概覽；若沒有工作階段則回報無法執行。
2. 查看讀取失敗提示。
Expected: 顯示讀取失敗訊息，不把失敗當成新的 0 人統計；不重設收入、不更動會員。

## Test 4 - 啟動碼多選複製、兌換暱稱與刪除限制
Viewport: desktop (1280x800) and mobile (375x667)
Covers: GET /api/data/activationCodes, multi-row selection, clipboard output, members.line_display_name, redeemed-code delete permission
Description: 使用已有授權管理員工作階段進行唯讀驗證；不建立或刪除啟動碼。若目前不足兩組啟動碼，明確回報資料前置條件不足，不建立測試資料。
Steps:
1. 以已有營運管理員工作階段開啟「啟動碼管理」。
2. 確認已兌換碼的「兌換會員」欄顯示 LINE 暱稱，而非會員 UUID。
3. 點擊「選取」，勾選目前列表中的兩組啟動碼，再點擊「複製」。
4. 檢查複製成功訊息與剪貼簿內容。
5. 比較未兌換碼與已兌換碼的刪除操作；再以已有超級管理員工作階段查看已兌換碼。
Expected: 選取模式顯示逐列核取方塊；複製內容依列表順序以換行分隔，畫面顯示已複製數量；營運管理員可刪除未兌換碼，但已兌換碼按鈕停用並顯示「已兌換，僅超級管理員可刪除」；超級管理員的已兌換碼刪除按鈕可用。全程不確認任何刪除。

## Test 5 - 轉帳申請卡片密度
Viewport: desktop (1280x800) and mobile (375x667)
Covers: GET /api/data/transferRequests, compact transfer request layout, responsive action placement
Description: 使用已有授權管理員工作階段進行唯讀驗證；不確認或拒絕轉帳申請。
Steps:
1. 以已有管理員工作階段開啟「訂閱管理」。
2. 查看「轉帳申請」區塊的標題、申請資訊、狀態與操作位置。
3. 分別以桌面與手機寬度檢查版面。
Expected: 區塊與每列使用緊湊間距，不出現過大的卡片留白；桌面操作靠右，手機的「確認」與「拒絕」維持同列且文字不直排；畫面沒有水平溢出。全程不點擊確認或拒絕。

## Test 7 - 後台清單完整性與權限
Viewport: mobile (375x667)
Covers: GET /api/data/:table, GET /api/dashboard, pagination and existing session guard
Description: 使用已有授權管理員工作階段讀取現有資料，不建立大量測試資料。成功登入後的過期 session 清理屬內部維護，1500ms 上限已由單元測試覆蓋，不以正式帳號反覆登入測試。
Steps:
1. 開啟用戶管理與訂閱管理，查看清單及本來的搜尋分頁功能。
2. 若現有資料超過 200 筆，搜尋第 201 筆以後已知存在的資料；資料不足則回報該項前置條件不足。
3. 開啟營運概覽並重新整理，確認統計可讀取。
Expected: 既有清單、搜尋與分頁可用；資料足夠時能找到 200 筆以後的紀錄；不修改會員、付款或任何清單資料。

## Test 8 - 超級管理員手機轉帳通知入口與權限
Viewport: mobile (375x667)
Covers: GET/POST/DELETE /api/admin-transfer-push, superadmin-only device enrollment, permission boundary, #transfer-requests navigation
Description: 僅使用既有管理員工作階段檢查；沒有帳號則回報無法執行，不建立帳號或轉帳申請，不發送測試通知、不替使用者允許通知權限。
Steps:
1. 以已有超級管理員工作階段開啟訂閱管理，查看轉帳申請的手機通知區塊。
2. 確認初始狀態來自伺服器，不會自動跳出通知權限要求；不支援的瀏覽器顯示說明。
3. 若可操作，按啟用並取消通知權限要求。
4. 開啟後台 #transfer-requests，確認登入後到達訂閱管理。
5. 使用既有一般管理員工作階段查看相同頁面；無工作階段時確認 API 不提供裝置資料。
Expected: 超級管理員可見手機通知控制；取消權限不顯示啟用成功；一般管理員不可見控制且不能操作 API；通知連結導向轉帳申請。POST/DELETE 裝置儲存與停用、後端派送及重試已由相關單元與交易回滾測試驗證，正式手機送達需使用者本人啟用後確認。
